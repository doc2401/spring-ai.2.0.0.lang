    Google GenAI 聊天

    Google GenAI API 允许开发者通过 Gemini Developer API 或 Vertex AI 使用 Google 的 Gemini 模型构建生成式 AI 应用程序。 Google GenAI API 支持多模态提示词作为输入，并输出文本或代码。 多模态模型能够处理来自多种模态的信息，包括图像、视频和文本。例如，您可以向模型发送一张一盘饼干的照片，并要求它提供这些饼干的食谱。

    Gemini 是由 Google DeepMind 开发的一系列生成式 AI 模型，旨在用于多模态场景。Gemini API 让您可以访问 各种模型，例如 Gemini Flash-Lite、Gemini Flash 或 Gemini Pro。

    此实现提供两种身份验证模式：

    • Gemini Developer API：使用 API 密钥进行快速原型设计和开发

    • Vertex AI：使用 Google Cloud 凭据进行具备企业级功能的生产环境部署

    Gemini API 参考

    Prerequisites

    请选择以下一种身份验证方法：

    选项 1：Gemini Developer API（API Key）

    • 从 Google AI Studio 获取 API 密钥

    • 将 API 密钥设置为环境变量或在您的应用程序属性中设置

    选项 2：Vertex AI (Google Cloud)

    • 安装适用于您操作系统的 gcloud CLI。

    • 运行以下命令进行身份验证。 将 PROJECT_ID 替换为您的 Google Cloud 项目 ID，将 ACCOUNT 替换为您的 Google Cloud 用户名。

    gcloud config set project <PROJECT_ID> &&
gcloud auth application-default login <ACCOUNT>

    Auto-configuration

    Spring AI 的自动配置中，starter 模块的 artifact 名称发生了重大变化。 请参阅 升级说明 获取更多信息。

    Spring AI 为 Google GenAI Chat Client 提供 Spring Boot 自动配置。 若要启用它，请将以下依赖添加到项目的 Maven pom.xml 或 Gradle build.gradle 构建文件中：

    • Maven

    • Gradle

    <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-google-genai</artifactId>
</dependency>
    dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-model-google-genai'
}
    请参阅 Dependency Management 部分，将 Spring AI BOM 添加到您的构建文件中。

    聊天属性

    启用和禁用聊天自动配置现在通过带有前缀 spring.ai.model.chat 的顶级属性进行配置。

    若要启用，请设置 spring.ai.model.chat=google-genai（默认已启用）

    若要禁用，请设置 spring.ai.model.chat=none（或任何不匹配 google-genai 的值）

    此更改是为了支持配置多个模型。

    连接属性

    前缀 spring.ai.google.genai 被用作属性前缀，让您能够连接到 Google GenAI。

    google-genai

    Gemini Developer API 的 API 密钥。如果提供该密钥，客户端将使用 Gemini Developer API 而非 Vertex AI。

    -

    spring.ai.google.genai.project-id

    Google Cloud Platform 项目 ID（Vertex AI 模式必需）

    -

    spring.ai.google.genai.location

    Google Cloud 区域（Vertex AI 模式必填）

    -

    spring.ai.google.genai.credentials-uri

    指向 Google Cloud 凭据的 URI。如果提供，它将用于创建 GoogleCredentials 实例进行身份验证。

    聊天模型属性

    前缀 spring.ai.google.genai.chat 是用于配置 Google GenAI Chat 对话模型实现的属性前缀。

    Property Description Default

    spring.ai.google.genai.chat.model

    支持使用的 Google GenAI Chat 模型，包括 gemini-2.5-flash、gemini-2.5-flash-lite、gemini-2.5-pro、gemini-3.1-pro-preview、gemini-3.1-flash-lite 和 gemini-3.5-flash。

    gemini-2.5-flash

    spring.ai.google.genai.chat.response-mime-type

    输出生成的候选文本的响应 MIME 类型。

    text/plain：(默认) 文本输出或 application/json：JSON 响应。

    spring.ai.google.genai.chat.google-search-retrieval

    使用 Google 搜索 Grounding 功能

    true or false, default false.

    spring.ai.google.genai.chat.include-server-side-tool-invocations

    当为 true 时，API 响应将在响应元数据中包含服务端工具调用和响应（例如 Google Search 调用），从而允许观察服务器的工具使用情况。仅支持 Gemini Developer API (MLDev)，不支持 Vertex AI。参见 Server-Side Tool Invocations。

    false

    spring.ai.google.genai.chat.temperature

    控制输出的随机性。数值范围为 [0.0, 1.0]（包含边界）。数值越接近 1.0，生成的响应越多样化；而数值越接近 0.0，生成模型给出的响应通常越少令人意外。

    -

    spring.ai.google.genai.chat.top-k

    采样时考虑的最大 token 数量。生成过程结合了 Top-k 和核采样（nucleus sampling）。Top-k 采样考虑概率最高的前 TopK 个 token 集合。

    -

    spring.ai.google.genai.chat.top-p

    采样时考虑的 token 的最大累计概率。生成过程结合了 Top-k 和核采样（nucleus sampling）。核采样考虑概率总和至少达到 topP 的最小 token 集合。

    -

    spring.ai.google.genai.chat.candidate-count

    要返回的生成响应消息的数量。此值必须在 [1, 8] 之间（包含边界）。默认为 1。

    1

    spring.ai.google.genai.chat.max-output-tokens

    可生成的最大 token 数量。

    -

    spring.ai.google.genai.chat.frequency-penalty

    用于减少重复的频率惩罚。

    -

    spring.ai.google.genai.chat.presence-penalty

    减少重复出现的缺勤处罚。

    -

    spring.ai.google.genai.chat.thinking-budget

    思考过程的思考预算。参见 思考配置。

    -

    spring.ai.google.genai.chat.thinking-level

    模型应生成的思考标记（thinking tokens）的级别。有效值：LOW、HIGH、THINKING_LEVEL_UNSPECIFIED。参见 思考配置。

    -

    spring.ai.google.genai.chat.include-thoughts

    为函数调用启用思维签名（thought signatures）。对于 Gemini 3 Pro，这是必须的，以避免在工具调用循环中出现验证错误。请参阅思维签名。

    false

    spring.ai.google.genai.chat.tool-callbacks

    用于与 ChatModel 注册的工具回调（Tool Callbacks）。

    -

    spring.ai.google.genai.chat.safety-settings

    用于控制安全过滤器的安全设置列表，定义参考自 Google GenAI Safety Settings。每个安全设置都可以包含方法、阈值和类别。

    -

    spring.ai.google.genai.chat.cached-content-name

    此请求中要使用的缓存内容名称。当与 use-cached-content=true 一起设置时，将使用缓存内容作为上下文。参见 Cached Content。

    -

    spring.ai.google.genai.chat.use-cached-content

    是否使用可用缓存内容。当为 true 且设置了 cached-content-name 时，系统将使用缓存内容。

    false

    spring.ai.google.genai.chat.auto-cache-threshold

    自动缓存超过此 token 阈值的提示词。当设置此项时，大于该值的提示词将自动缓存以供重复使用。设置为 null 可禁用自动缓存。

    -

    spring.ai.google.genai.chat.auto-cache-ttl

    自动缓存内容的生存时间（Duration），采用 ISO-8601 格式（例如，PT1H 表示 1 小时）。当启用自动缓存时使用。

    PT1H

    spring.ai.google.genai.chat.enable-cached-content

    启用 GoogleGenAiCachedContentService 豆（bean）以管理缓存内容。

    true

    spring.ai.google.genai.chat.service-tier

    请求使用的服务层级。有效值：STANDARD、PRIORITY、FLEX。

    -
    所有以 spring.ai.google.genai.chat 为前缀的属性都可以通过在 Prompt 调用中添加特定于请求的 运行时选项 来在运行时覆盖。

    运行时选项

    GoogleGenAiChatOptions.java 提供了模型配置，例如 temperature、topK 等。

    在启动时，可以通过 GoogleGenAiChatModel(client, options) 构造函数或 spring.ai.google.genai.chat.* 属性来配置默认选项。

    在运行时，您可以通过在 Prompt 调用中添加新的、针对特定请求的选项来覆盖默认选项。 例如，要为特定请求覆盖默认的 temperature：

    ChatResponse response = chatModel.call(
    new Prompt(
        "Generate the names of 5 famous pirates.",
        GoogleGenAiChatOptions.builder()
            .temperature(0.4)
        .build()
    ));
    除了模型特定的 GoogleGenAiChatOptions，您还可以使用通过 ChatOptions#builder() 创建的可移植 ChatOptions 实例。

    工具调用

    GoogleGenAiChatModel 不在内部执行工具调用。 必须使用以下两种支持的方法之一在外部处理工具执行。

    通过 ChatClient 进行工具调用（推荐）

    推荐的方法是使用带有 ToolCallingAdvisor 的 ChatClient，它会自动注册并透明地管理同步和流式场景下的工具调用循环。

    public class WeatherService {

    @Tool(description = "Get the weather in location")
    public String weatherByLocation(@ToolParam(description= "City or state name") String location) {
        ...
    }
}

String response = ChatClient.create(this.chatModel)
        .prompt("What's the weather like in Boston?")
        .tools(new WeatherService())
        .call()
        .content();

    您还可以注册一个 ToolCallback 类型的 bean 并直接传递：

    @Bean
ToolCallback weatherFunction() {
    return FunctionToolCallback.builder("weatherFunction", new MockWeatherService())
        .description("Get the weather in location. Return temperature in 36°F or 36°C format.")
        .inputType(Request.class)
        .build();
}

String response = ChatClient.create(this.chatModel)
        .prompt("What's the weather like in Boston?")
        .tools(weatherFunction)
        .call()
        .content();

    用户控制的工具执行

    当您需要直接访问 ChatModel API 并希望完全控制工具调用循环（tool-call loop）时，请使用此模式。 直接调用 ChatModel 而不使用 ToolCallingAdvisor；自行检查工具调用，并使用 ToolCallingManager 来驱动循环。

    ToolCallingManager toolCallingManager = ToolCallingManager.builder().build();

GoogleGenAiChatOptions options = GoogleGenAiChatOptions.builder()
        .toolCallbacks(ToolCallbacks.from(new WeatherService()))
        .build();

Prompt prompt = new Prompt("What's the weather like in Boston?", options);
ChatResponse response = chatModel.call(prompt);

while (response.hasToolCalls()) {
    ToolExecutionResult toolExecutionResult = toolCallingManager.executeToolCalls(prompt, response);
    prompt = new Prompt(toolExecutionResult.conversationHistory(), options);
    response = chatModel.call(prompt);
}

    在 Tools 文档中查找更多内容。

    服务端工具调用

    当通过 googleSearchRetrieval(true) 启用 Google Search 或其他服务端工具时，模型会在服务器上执行这些工具。默认情况下，这些调用对客户端是不可见的——您只能看到最终的文本响应。设置 includeServerSideToolInvocations(true) 会使 API 在响应内容中包含服务器的工具调用和响应，让您可以观察到模型搜索了什么以及获得了哪些结果。

    此功能仅支持 Gemini Developer API（MLDev / API 密钥身份验证）。它在 Vertex AI 上不被支持。

    Configuration

    通过应用程序属性启用：

    spring.ai.google.genai.chat.google-search-retrieval=true
spring.ai.google.genai.chat.include-server-side-tool-invocations=true

    或者在运行时通过程序方式：

    ChatResponse response = chatModel.call(
    new Prompt(
        "What are the latest developments in quantum computing?",
        GoogleGenAiChatOptions.builder()
            .model("gemini-2.0-flash")
            .googleSearchRetrieval(true)
            .includeServerSideToolInvocations(true)
            .build()
    ));

    访问服务端工具调用元数据

    启用后，服务器端工具调用将可在响应消息元数据中的 serverSideToolInvocations 键下获取：

    ChatResponse response = chatModel.call(prompt);

Map<String, Object> metadata = response.getResult().getOutput().getMetadata();

List<Map<String, Object>> invocations =
    (List<Map<String, Object>>) metadata.get("serverSideToolInvocations");

if (invocations != null) {
    for (Map<String, Object> invocation : invocations) {
        String type = (String) invocation.get("type");       // "toolCall" or "toolResponse"
        String id = (String) invocation.get("id");            // Unique invocation ID
        String toolType = (String) invocation.get("toolType"); // e.g., "GOOGLE_SEARCH_WEB"

        if ("toolCall".equals(type)) {
            Map<String, Object> args = (Map<String, Object>) invocation.get("args");
            // Inspect what the model searched for
        } else if ("toolResponse".equals(type)) {
            Map<String, Object> responseData = (Map<String, Object>) invocation.get("response");
            // Inspect what search results the model received
        }
    }
}

    列表中的每个条目包含：

    Field Description

    type

    要么是 "toolCall"（模型的调用请求），要么是 "toolResponse"（服务器的返回结果）

    id

    将 toolCall 与其对应的 toolResponse 关联的唯一标识符

    toolType

    服务端工具的类型（例如，GOOGLE_SEARCH_WEB、GOOGLE_SEARCH_IMAGE、URL_CONTEXT、GOOGLE_MAPS）

    args

    (仅限工具调用) 传递给工具的参数

    response

    (toolResponse only) 工具返回的结果

    结合函数调用

    服务端工具调用与客户端函数调用协同工作。您可以在同一个请求中同时启用 Google Search（服务端）和自定义函数（客户端）：

    ChatResponse response = chatModel.call(
    new Prompt(
        "What's the weather in San Francisco? Also search for the latest news about the city.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-2.0-flash")
            .googleSearchRetrieval(true)
            .includeServerSideToolInvocations(true)
            .toolCallbacks(List.of(
                FunctionToolCallback.builder("get_current_weather", new WeatherService())
                    .description("Get the current weather in a given location")
                    .inputType(WeatherRequest.class)
                    .build()))
            .build()
    ));

// The response contains:
// - Weather data from the client-side function call (executed locally)
// - Google Search invocations visible in metadata (executed server-side)
    服务端工具调用仅用于观测——客户端不会执行它们。为了避免干扰工具执行循环，它们在元数据中与客户端函数调用分开展示。

    思考配置

    Gemini 模型支持“思考”能力，允许模型在生成响应之前进行更深层次的推理。这通过 ThinkingConfig 进行控制，其中包含三个相关选项：thinkingBudget、thinkingLevel 和 includeThoughts。

    思考层级

    thinkingLevel 选项控制模型生成的推理 token 的深度。此选项适用于支持思考功能的模型（例如 Gemini 3 Pro Preview）。

    Value Description

    THINKING_LEVEL_UNSPECIFIED

    模型使用其默认行为。

    MINIMAL

    适用于大多数查询的“不思考”设置。最小化延迟。

    LOW

    低思考。极少的推理 Token。

    MEDIUM

    大多数任务均采用平衡思维。

    HIGH

    深度思考。用于需要深入分析和逐步推理的复杂问题。

    通过属性进行配置

    spring.ai.google.genai.chat.model=gemini-3.1-pro-preview
spring.ai.google.genai.chat.thinking-level=HIGH

    程序化配置

    import org.springframework.ai.google.genai.common.GoogleGenAiThinkingLevel;

ChatResponse response = chatModel.call(
    new Prompt(
        "Explain the theory of relativity in simple terms.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-3.1-pro-preview")
            .thinkingLevel(GoogleGenAiThinkingLevel.HIGH)
            .build()
    ));

    思考预算

    thinkingBudget 选项为思考过程设置了 token 预算：

    • 正值：思考的最大 token 数量（例如，8192）

    • 零 (0)：完全禁用思考

    • 未设置：模型根据查询复杂度自动决定

    ChatResponse response = chatModel.call(
    new Prompt(
        "Solve this complex math problem step by step.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-2.5-pro")
            .thinkingBudget(8192)
            .build()
    ));

    选项兼容性

    thinkingLevel 和 thinkingBudget 是互斥的。 您不能在同一个请求中使用两者——这样做会导致 API 错误。

    • 对于 Gemini 3.x 模型，请使用 thinkingLevel。Gemini 3 Pro 仅支持 LOW 和 HIGH；Gemini 3 Flash 模型支持所有级别（MINIMAL、LOW、MEDIUM、HIGH）。

    • 对于 Gemini 2.5 系列模型，请使用 thinkingBudget（Token 数量）。

    您可以将 includeThoughts 与 thinkingLevel 或 thinkingBudget 其中之一结合使用（但不能同时使用两者）：

    // For Gemini 3.x (e.g. Pro): use thinkingLevel + includeThoughts
ChatResponse response = chatModel.call(
    new Prompt(
        "Analyze this complex scenario.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-3.1-pro-preview")
            .thinkingLevel(GoogleGenAiThinkingLevel.HIGH)
            .includeThoughts(true)
            .build()
    ));

// For Gemini 2.5: use thinkingBudget + includeThoughts
ChatResponse response = chatModel.call(
    new Prompt(
        "Analyze this complex scenario.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-2.5-pro")
            .thinkingBudget(8192)
            .includeThoughts(true)
            .build()
    ));

    思考配置选项是特定于模型的：

    模型 模型 ID thinkingLevel thinkingBudget 备注

    ❌ 不支持

    Gemini 2.5 Pro

    ❌ 不支持

    ✅ Supported

    思想签名

    Gemini 3 Pro 引入了 thought signatures（思维签名），它们是用于在函数调用过程中保留模型推理上下文的不透明字节数组。当启用 includeThoughts 时，模型将返回 thought signatures，这些签名必须在工具调用循环中的同一轮次内传回。

    当思维特征变得重要时

    重要提示：思维签名验证仅适用于当前轮次——具体而言，是在模型进行函数调用（包括并行和顺序调用）的工具调用循环期间。API不会验证对话历史中先前轮次的思维签名。

    根据 Google 的文档：

    • 验证仅强制执行当前轮次内的函数调用。

    • 之前的轮次签名不需要保留

    • 当前轮次函数调用中缺失签名会导致 Gemini 3 Pro 出现 HTTP 400 错误

    • 对于并行函数调用，只有第一个 functionCall 部分包含签名。

    对于 Gemini 2.5 Pro 及更早的模型，thought signatures 是可选的，且 API 具有较高的容错性。

    通过 ChatClient 自动处理（推荐）

    在使用 ChatClient 配合 ToolCallingAdvisor（推荐做法）时，Spring AI 会自动处理思考签名（thought signatures）：

    1. Extracts 从模型响应中提取思维签名

    2. 将它们附加到返回函数响应时的正确 functionCall 部分

    3. 正确传播它们在单轮内的函数调用（包括并行和顺序调用）中

    @Bean
ToolCallback weatherFunction() {
    return FunctionToolCallback.builder("weatherFunction", new WeatherService())
        .description("Get the weather in a location")
        .inputType(WeatherRequest.class)
        .build();
}

// Enable includeThoughts for Gemini 3 Pro with function calling
String response = ChatClient.create(this.chatModel)
        .prompt("What's the weather like in Boston?")
        .options(GoogleGenAiChatOptions.builder()
            .model("gemini-3.1-pro-preview")
            .includeThoughts(true)
            .build())
        .tools(weatherFunction)
        .call()
        .content();

    带有思维签名的用户控制工具执行

    在使用手动工具执行循环时，您必须通过在对话历史中保留原始的 AssistantMessage（及其元数据）来保留思维签名。Spring AI 在转换消息时会自动将签名附加到正确的 functionCall 部分。

    带有思维签名的手动工具执行要求：

    1. 从响应元数据中提取思维签名：

      AssistantMessage assistantMessage = response.getResult().getOutput();
Map<String, Object> metadata = assistantMessage.getMetadata();
List<byte[]> thoughtSignatures = (List<byte[]>) metadata.get("thoughtSignatures");

    2. 在返回函数响应时，请在消息历史记录中包含原始的 AssistantMessage 及其完整的元数据。Spring AI 将自动将思考签名（thought signatures）附加到正确的 functionCall 部分。

    3. 对于 Gemini 3 Pro，如果在当前轮次中未能保留思维签名（thought signatures），将导致 API 返回 HTTP 400 错误。

    只有当前轮次的函数调用需要思维签名（thought signatures）。在开始新的对话轮次时（完成一轮函数调用后），您不需要保留上一轮的签名。
    启用 includeThoughts 会增加 Token 的消耗，因为思考过程将被包含在响应中。这会影响 API 成本，但能提供更好的推理透明度。

    缓存内容

    Google GenAI 的 Context Caching 允许您缓存大量内容（如长文档、代码库或媒体文件），并在多次请求中重复使用。这显著降低了 API 成本，并缩短了针对相同内容的重复查询的响应延迟。

    Benefits

    • 降低成本：缓存的 token 的计费标准远低于常规输入 token（通常便宜 75-90%）

    • 性能提升：重用缓存内容可减少大型上下文的处理时间

    • 一致性：相同的缓存上下文确保了多次请求中的响应保持一致

    缓存要求

    • 最小缓存大小：32,768 个 token（约 25,000 字）

    • 最大缓存时长：默认 1 小时（可通过 TTL 进行配置）

    • 缓存内容必须包含系统指令或对话历史

    使用缓存内容服务

    Spring AI 提供 GoogleGenAiCachedContentService 用于程序化的缓存管理。当使用 Spring Boot 自动配置时，该服务会自动配置。

    创建缓存内容

    @Autowired
private GoogleGenAiCachedContentService cachedContentService;

// Create cached content with a large document
String largeDocument = "... your large context here (>32k tokens) ...";

CachedContentRequest request = CachedContentRequest.builder()
    .model("gemini-2.5-flash")
    .contents(List.of(
        Content.builder()
            .role("user")
            .parts(List.of(Part.fromText(largeDocument)))
            .build()
    ))
    .displayName("My Large Document Cache")
    .ttl(Duration.ofHours(1))
    .build();

GoogleGenAiCachedContent cachedContent = cachedContentService.create(request);
String cacheName = cachedContent.getName(); // Save this for reuse

    在聊天请求中使用缓存内容

    一旦您创建了缓存内容，请在您的聊天请求中引用它：

    ChatResponse response = chatModel.call(
    new Prompt(
        "Summarize the key points from the document",
        GoogleGenAiChatOptions.builder()
            .useCachedContent(true)
            .cachedContentName(cacheName) // Use the cached content name
            .build()
    ));

    或者通过配置属性：

    spring.ai.google.genai.chat.use-cached-content=true
spring.ai.google.genai.chat.cached-content-name=cachedContent/your-cache-name

    管理缓存内容

    GoogleGenAiCachedContentService 提供全面的缓存管理：

    // Retrieve cached content
GoogleGenAiCachedContent content = cachedContentService.get(cacheName);

// Update cache TTL
CachedContentUpdateRequest updateRequest = CachedContentUpdateRequest.builder()
    .ttl(Duration.ofHours(2))
    .build();
GoogleGenAiCachedContent updated = cachedContentService.update(cacheName, updateRequest);

// List all cached content
List<GoogleGenAiCachedContent> allCaches = cachedContentService.listAll();

// Delete cached content
boolean deleted = cachedContentService.delete(cacheName);

// Extend cache TTL
GoogleGenAiCachedContent extended = cachedContentService.extendTtl(cacheName, Duration.ofMinutes(30));

// Cleanup expired caches
int removedCount = cachedContentService.cleanupExpired();

    异步操作

    所有操作都有异步变体：

    CompletableFuture<GoogleGenAiCachedContent> futureCache =
    cachedContentService.createAsync(request);

CompletableFuture<GoogleGenAiCachedContent> futureGet =
    cachedContentService.getAsync(cacheName);

CompletableFuture<Boolean> futureDelete =
    cachedContentService.deleteAsync(cacheName);

    Auto-Caching

    当大型提示词（prompts）超过指定的 token 阈值时，Spring AI 可以自动对其进行缓存：

    # Automatically cache prompts larger than 100,000 tokens
spring.ai.google.genai.chat.auto-cache-threshold=100000
# Set auto-cache TTL to 1 hour
spring.ai.google.genai.chat.auto-cache-ttl=PT1H

    或者通过程序方式：

    ChatResponse response = chatModel.call(
    new Prompt(
        largePrompt,
        GoogleGenAiChatOptions.builder()
            .autoCacheThreshold(100000)
            .autoCacheTtl(Duration.ofHours(1))
            .build()
    ));
    自动缓存适用于一次性的长上下文。对于重复使用相同的上下文，手动创建并引用缓存内容效率更高。

    监控缓存使用情况

    缓存内容包括可通过该服务访问的使用元数据：

    GoogleGenAiCachedContent content = cachedContentService.get(cacheName);

// Check if cache is expired
boolean expired = content.isExpired();

// Get remaining TTL
Duration remaining = content.getRemainingTtl();

// Get usage metadata
CachedContentUsageMetadata metadata = content.getUsageMetadata();
if (metadata != null) {
    System.out.println("Total tokens: " + metadata.totalTokenCount().orElse(0));
}

    最佳实践

    1. 缓存生命周期：根据您的使用场景设置合适的 TTL。对于频繁变化的内容，设置较短的 TTL；对于静态内容，设置较长的 TTL。

    2. 缓存命名：使用具有描述性的显示名称，以便轻松识别缓存内容。

    3. 清理：定期清理过期的缓存以保持整洁。

    4. Token 阈值：仅缓存超过最低阈值（32,768 tokens）的内容。

    5. 成本优化：复用多个请求中的缓存内容，以最大限度地节省成本。

    这将创建一个 GoogleGenAiChatModel 实现，您可以将其注入到您的类中。 这是一个使用该聊天模型进行文本生成的简单 @Controller 类示例。

    @RestController
public class ChatController {

    private final GoogleGenAiChatModel chatModel;

    @Autowired
    public ChatController(GoogleGenAiChatModel chatModel) {
        this.chatModel = chatModel;
    }

    @GetMapping("/ai/generate")
    public Map generate(@RequestParam(value = "message", defaultValue = "Tell me a joke") String message) {
        return Map.of("generation", this.chatModel.call(message));
    }

    @GetMapping("/ai/generateStream")
	public Flux<ChatResponse> generateStream(@RequestParam(value = "message", defaultValue = "Tell me a joke") String message) {
        Prompt prompt = new Prompt(new UserMessage(message));
        return this.chatModel.stream(prompt);
    }
}

    <dependency>
    <groupId>org.springframework.ai</groupId>

</dependency>

    dependencies {
    implementation 'org.springframework.ai:spring-ai-google-genai'
}

ChatResponse response = this.chatModel.call(

    Client genAiClient = Client.builder()
