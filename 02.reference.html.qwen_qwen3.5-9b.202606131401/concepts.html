    人工智能概念

    本节介绍了 Spring AI 使用的核心概念。我们建议您仔细阅读，以深入理解 Spring AI 的实现原理。

    Models

    人工智能模型是旨在处理和生成信息的算法，通常模仿人类的认知功能。通过从大型数据集中学习模式和见解，这些模型能够进行预测、生成文本、图像或其他输出，从而增强各行业中的各种应用。

    存在多种不同类型的 AI 模型，每种都适用于特定的使用场景。虽然 ChatGPT 及其生成式 AI 能力通过文本输入和输出吸引了大量用户，但许多模型和公司提供了多样化的输入与输出方式。在 ChatGPT 出现之前，许多人就对文生图模型如 Midjourney 和 Stable Diffusion 着迷不已。

    Spring AI 目前支持将输入和输出处理为语言、图像和音频的模型。 前一张表格的最后一行，其输入为文本并输出数字，通常被称为嵌入（embedding）文本，它代表了 AI 模型中使用的内部数据结构。 Spring AI 已支持嵌入功能，以启用更高级的使用场景。

    与 GPT 等模型的区别在于其预训练特性，正如"GPT"中的"P"所示——即“生成式预训练Transformer"（Generative Pre-trained Transformer）。这一预训练功能将人工智能转变为一种通用开发工具，无需具备广泛的机器学习或模型训练背景即可使用。

    Prompts

    提示是引导人工智能模型生成特定输出的基于语言的输入的基础。 对于熟悉 ChatGPT 的人来说，提示可能看起来只是输入到对话框中并发送到 API 的文本。 然而，它包含的内容远不止于此。 在许多人工智能模型中，提示的文本不仅仅是一个简单的字符串。

    ChatGPT 的 API 在提示词中包含多个文本输入，每个文本输入都会被分配一个角色。例如，有系统角色（system role），它告诉模型如何行为并为交互设定上下文；还有用户角色（user role），这通常是用户的输入。

    编写有效的提示词既是一门艺术，也是一门科学。 ChatGPT 是为人类对话而设计的。 这与使用类似 SQL 的“提问”方式截然不同。 必须像与另一个人交谈一样与人工智能模型进行交流。

    这种交互方式的重要性催生了“提示工程”这一独立学科。 涌现出大量旨在提升提示有效性的技术方法。 投入时间精心构建提示，可显著改善最终输出结果。

    分享提示词已成为一种集体实践，学术界也在积极研究这一主题。 以创建有效提示词可能违背直觉为例（例如与 SQL 对比），一篇近期研究论文发现，最有效的提示之一是以“深吸一口气，逐步完成此任务”开头。 这足以说明语言为何如此重要。 我们尚未完全掌握如何最有效地利用该技术的前代版本（如 ChatGPT 3.5），更不用说那些正在开发中的新版本了。

    提示模板

    创建有效的提示词需要明确请求的上下文，并将请求中的部分内容替换为用户输入的具体值。

    该流程使用传统的基于文本的模板引擎来创建和管理提示。Spring AI 采用开源库 StringTemplate 来实现此功能。

    例如，考虑以下简单的提示模板：

    Tell me a {adjective} joke about {content}.

    在 Spring AI 中，提示模板可以类比为 Spring MVC 架构中的“视图”。 通常提供一个模型对象（一般为 java.util.Map）来填充模板中的占位符。 渲染后的字符串将成为提供给 AI 模型的提示内容。

    发送给模型的具体提示数据格式存在相当大的差异。最初，提示仅为简单的字符串，随后已演变为包含多条消息的格式，其中每条消息中的每个字符串都代表模型的一个不同角色。

    Embeddings

    嵌入（Embeddings）是文本、图像或视频的数值表示形式，能够捕捉输入之间的关系。

    嵌入通过将文本、图像和视频转换为浮点数数组（称为向量）来工作。这些向量旨在捕捉文本、图像和视频的含义。嵌入数组的长度被称为向量的维度。

    通过计算两个文本片段的向量表示之间的数值距离，应用程序可以确定用于生成嵌入向量的对象之间的相似性。

    作为探索人工智能的 Java 开发者，无需深入理解这些向量表示背后复杂的数学理论或具体实现。只需对其在人工智能系统中的角色和功能有基本了解即可，尤其是在将人工智能功能集成到您的应用程序时。

    嵌入向量在诸如检索增强生成（RAG）等实际应用中尤为重要。它们能够将数据表示为语义空间中的点，这类似于欧几里得几何中的二维空间，但处于更高维度。这意味着，正如欧几里得几何中平面上的点根据其坐标的远近而彼此接近或遥远一样，在语义空间中，点的邻近程度反映了其含义的相似性。关于相似主题的语句在该多维空间中位置更为接近，就像图表上彼此靠近的点一样。这种邻近性有助于文本分类、语义搜索甚至产品推荐等任务，因为它使人工智能能够根据这些概念在此扩展语义景观中的“位置”来识别和归类相关概念。

    您可以将这个语义空间视为一个向量。

    Tokens

    Token 是人工智能模型运作的基本构建单元。在输入阶段，模型将单词转换为 token；在输出阶段，它们再将 token 转换回单词。

    在英语中，一个 token 大约对应一个单词的 75%。作为参考，莎士比亚的全部作品总字数约为 90 万词，换算成 token 则约为 120 万个。

    更为重要的是，Tokens 等同于货币。 在托管的 AI 模型语境下，您的费用取决于所使用的 Token 数量。输入和输出均计入总 Token 数。

    此外，模型还受到令牌数量限制，这限制了单次 API 调用中可处理的文本量。该阈值通常被称为“上下文窗口”。超出此限制的文本不会被模型处理。

    例如，ChatGPT-3 的上下文窗口限制为 4K 个 token，而 GPT-4 则提供多种选项，包括 8K、16K 和 32K。Anthropic 的 Claude AI 模型拥有 100K token 的限制，而 Meta 最近的研究成果则推出了一款支持 1M token 限制的模型。

    要使用 GPT-4 总结莎士比亚的著作，你需要制定软件工程策略来分割数据，并在模型的上下文窗口限制内呈现这些数据。Spring AI 项目可以帮助你完成这项任务。

    结构化输出

    AI 模型的输出传统上以 java.lang.String 形式呈现，即使你要求回复为 JSON 格式。 它可能是一个正确的 JSON，但它并不是一个 JSON 数据结构，而仅仅是一个字符串。 此外，在提示词中要求“JSON"也并非百分之百准确。

    这种复杂性催生了一个专门领域，即创建提示以生成预期输出，随后将生成的简单字符串转换为可应用集成的可用数据结构。

    结构化输出转换采用精心设计的提示词，通常需要与模型进行多次交互才能实现所需的格式。

    将您的数据与 API 引入 AI 模型

    如何为尚未接受过训练的 AI 模型提供相关信息？

    请注意，GPT 3.5/4.0 的数据集仅更新至 2021 年 9 月。因此，对于需要该日期之后知识的问题，模型会表示不知道答案。一个有趣的冷知识是，该数据集的容量约为 650GB。

    有三种技术可用于定制 AI 模型以融入您的数据：

    • 微调：这是一种传统的机器学习技术，涉及调整模型并改变其内部权重。然而，对于机器学习专家而言，这是一个具有挑战性的过程；而对于像 GPT 这样的大型模型来说，由于模型规模庞大，该过程极其消耗资源。此外，某些模型可能并不提供此选项。

    • 提示词填充：一种更实用的替代方案是将您的数据嵌入到提供给模型的系统提示中。鉴于模型的令牌限制，需要采用特定技术将相关数据呈现于模型的上下文窗口内。这种方法在通俗语境中被称为“填充提示词”。Spring AI 库可帮助您实现基于“填充提示词”技术的解决方案，该技术亦称为检索增强生成（RAG）。

    • 工具调用：该技术允许注册工具（用户定义的服务），将大语言模型与外部系统的 API 连接起来。Spring AI 极大地简化了您需要编写以支持工具调用的代码。

    检索增强生成

    一种称为检索增强生成（Retrieval Augmented Generation，简称 RAG）的技术应运而生，旨在解决将相关数据整合到提示中以生成准确人工智能模型响应这一挑战。

    该方法采用批处理风格的编程模型，其中任务从文档中读取非结构化数据，对其进行转换，然后将其写入向量数据库。 从高层来看，这是一个 ETL（提取、转换和加载）管道。 该向量数据库用于 RAG 技术中的检索部分。

    作为将非结构化数据加载到向量数据库的一部分，最重要的转换之一是将原始文档拆分为更小的片段。 将原始文档拆分为更小片段的程序包含两个关键步骤：

    1. 将文档按语义边界拆分为多个部分。例如，对于包含段落和表格的文档，应避免在段落或表格中间进行拆分。对于代码，应避免在方法的实现过程中进行拆分。

    2. 将文档的各个部分进一步拆分为大小仅为 AI 模型令牌限制一小百分比的部分。

    RAG 的下一阶段是处理用户输入。 当需要由 AI 模型回答用户问题时，会将该问题以及所有“相似”的文档片段放入发送给 AI 模型的提示词中。 这正是使用向量数据库的原因，它在查找相似内容方面表现出色。

    • ETL Pipeline 提供了关于编排从数据源提取数据并将其存储到结构化向量存储中的流程的更多信息，确保在将数据传递给 AI 模型时，数据处于检索所需的最佳格式。

    • ChatClient - 检索增强生成 解释了如何使用 QuestionAnswerAdvisor 在您的应用程序中启用 RAG 功能。

    工具调用

    大语言模型（LLM）在训练完成后即被冻结，导致其知识过时，且无法访问或修改外部数据。

    工具调用机制解决了这些不足。它允许您将自定义服务注册为工具，从而将大语言模型与外部系统的 API 连接起来。这些系统可以为 LLM 提供实时数据，并代表其执行数据处理操作。

    Spring AI 极大地简化了编写支持工具调用的代码。它会自动处理工具调用的对话流程。您只需提供一个带有@Tool注解的方法，并将其添加到提示选项中以供模型使用。此外，您可以在单个提示中定义并引用多个工具。

    1. 当我们要向模型提供工具时，会在聊天请求中包含该工具的定义。每个工具定义包括名称、描述以及输入参数的模式（schema）。

    2. 当模型决定调用工具时，它会发送一个响应，其中包含工具名称和按照定义的模式构建的输入参数。

    3. 该应用程序负责使用工具名称来识别并执行带有所提供输入参数的工具。

    4. 应用程序处理工具调用的结果。

    5. 应用程序将工具调用结果返回给模型。

    6. 模型利用工具调用的结果作为额外上下文来生成最终响应。

    有关如何使用此功能与不同的 AI 模型，请遵循工具调用文档以获取更多信息。

    评估人工智能的回复

    有效评估人工智能系统对用户请求的响应，对于确保最终应用的准确性和实用性至关重要。 几种新兴技术使得利用预训练模型本身来实现这一目的成为可能。

    该评估过程涉及分析生成的回复是否与用户意图及查询上下文相一致。相关性、连贯性和事实准确性等指标用于衡量人工智能生成回复的质量。

    一种方法是将用户的请求和 AI 模型的响应同时呈现给模型，以查询该响应是否与提供的数据一致。

    此外，利用向量数据库中存储的信息作为补充数据，可以增强评估过程，有助于确定响应的相关性。

    Spring AI 项目提供了一个 `Evaluator` API，目前可访问用于评估模型响应的基本策略。有关更多信息，请遵循评估测试文档。
