    Prompts

    提示是引导人工智能模型生成特定输出的输入。这些提示的设计和措辞会显著影响模型的响应。

    在 Spring AI 中与 AI 模型进行最低级别的交互时，处理提示（prompts）的方式与 Spring MVC 中管理“视图”有些相似。 这涉及创建包含动态内容占位符的长文本。 这些占位符随后会根据用户请求或应用程序中的其他代码进行替换。 另一个类比是包含特定表达式占位符的 SQL 语句。

    随着 Spring AI 的发展，它将引入更高层次的抽象来与 AI 模型进行交互。 本节中描述的基础类在角色和功能上可以比作 JDBC。 例如，ChatModel 类类似于 JDK 中的核心 JDBC 库。 ChatClient 类则建立在 ChatModel 之上，可类比于 JdbcClient，并通过 Advisor 提供更高级的构建能力，以考虑与模型的过往交互、通过附加上下文文档增强提示，并引入代理行为。

    提示的结构在人工智能领域随时间不断演变。 最初，提示只是简单的字符串。 随着时间的推移，它们逐渐发展为包含特定输入占位符的形式，例如 AI 模型能够识别的"USER:"。 OpenAI 通过在使用前将多条消息字符串划分为不同的角色，为提示引入了更丰富的结构。

    API 概述

    Prompt

    通常使用 `ChatModel` 的 `call()` 方法，该方法接收一个 `Prompt` 实例并返回一个 `ChatResponse`。

    `Prompt` 类作为容器，用于组织一系列 `Message` 对象和一个请求 `ChatOptions`。 每个 `Message` 在提示中代表一个独特的角色，其内容和意图各不相同。 这些角色可以涵盖多种元素，从用户提问到 AI 生成的回复，再到相关的背景信息。 这种结构使得与 AI 模型的交互变得复杂而细致，因为提示由多个消息组成，每条消息都被分配了特定的对话角色。

    以下是省略了构造函数和实用方法以简化篇幅的 Prompt 类的截断版本：

    public class Prompt implements ModelRequest<List<Message>> {

    private final List<Message> messages;

    private ChatOptions chatOptions;
}

    便捷方法

    `Prompt` 类提供了多种便捷方法，可根据角色访问消息：

    单条消息访问：

    • `getUserMessage()`：返回提示中的最后一条用户消息，若不存在则返回空的 `UserMessage`。

    • getSystemMessage()：返回提示中的第一个系统消息，如果不存在则返回空的 SystemMessage。

    • `getLastUserOrToolResponseMessage()`：返回最后一条用户或工具响应消息，有助于保持对话的连贯性。

    多消息访问：

    • getUserMessages()：返回提示中所有用户消息的列表，并保持其顺序。

    • getSystemMessages()：返回提示中所有系统消息的列表，并保持其顺序。

    这些方法在处理多轮对话或需要按角色处理消息时特别有用。

    Message

    `Message` 接口封装了 `Prompt` 文本内容、一组元数据属性以及一个名为 `MessageType` 的分类。

    接口定义如下：

    public interface Content {

	String getContent();

	Map<String, Object> getMetadata();
}

public interface Message extends Content {

	MessageType getMessageType();
}

    多模态消息类型同样实现了MediaContent接口，提供一份Media内容对象列表。

    public interface MediaContent extends Content {

	Collection<Media> getMedia();

}

    `Message` 接口的各种实现对应于 AI 模型可以处理的不同类别的消息。 模型根据对话角色来区分消息类别。

    这些角色通过下文讨论的 `MessageType` 进行有效映射。

    Roles

    每条消息都被分配了特定的角色。 这些角色对消息进行分类，阐明提示中每个部分的情境和目的，以便人工智能模型理解。 这种结构化方法增强了与人工智能沟通的细微差别和有效性，因为提示中的每一部分在交互中都扮演着独特且明确的角色。

    主要职责如下：

    • 系统角色：指导 AI 的行为和响应风格，设定 AI 解释和回复输入的参数或规则。这类似于在开始对话之前向 AI 提供指令。

    • 用户角色：代表用户的输入，包括其向 AI 提出的问题、命令或陈述。该角色至关重要，因为它是 AI 生成回复的基础。

    • 助手角色：AI 对用户输入的回应。 这不仅仅是提供一个答案或做出反应，对于保持对话的流畅性至关重要。 通过追踪 AI 之前的回应（即“助手角色”消息），系统能够确保交互具有连贯性和上下文相关性。 助手消息可能还包含函数工具调用请求信息。 这就像是 AI 的一项特殊功能，在需要执行特定任务时使用，例如计算、获取数据或超出单纯对话范围的其他操作。

    • 工具/函数角色：该工具/函数角色专注于响应工具调用助手消息，返回附加信息。

    在 Spring AI 中，角色以枚举形式表示，如下所示：

    public enum MessageType {

	USER("user"),

	ASSISTANT("assistant"),

	SYSTEM("system"),

	TOOL("tool");

    ...
}

    PromptTemplate

    Spring AI 中用于提示词模板化的关键组件是 `PromptTemplate` 类，它旨在促进结构化提示词的创建，以便随后将这些提示词发送给 AI 模型进行处理。

    public class PromptTemplate implements PromptTemplateActions, PromptTemplateMessageActions {

    // Other methods to be discussed later
}

    该类使用 TemplateRenderer API 来渲染模板。默认情况下，Spring AI 使用基于 Terence Parr 开发的开源 StringTemplate 引擎的 StTemplateRenderer 实现。模板变量通过 {} 语法进行标识，但您也可以配置分隔符以使用其他语法。

    public interface TemplateRenderer extends BiFunction<String, Map<String, Object>, String> {

	@Override
	String apply(String template, Map<String, Object> variables);

}

    Spring AI 使用 `TemplateRenderer`接口来处理将变量实际替换到模板字符串中的操作。默认实现使用了[StringTemplate]。如果您需要自定义逻辑，可以提供自己的 `TemplateRenderer`实现。对于不需要模板渲染的场景（例如模板字符串已经完整），您可以使用提供的 `NoOpTemplateRenderer`。

    使用自定义的 StringTemplate 渲染器，并采用'<'和'>'作为分隔符的示例。
    PromptTemplate promptTemplate = PromptTemplate.builder()
    .renderer(StTemplateRenderer.builder().startDelimiterToken('<').endDelimiterToken('>').build())
    .template("""
            Tell me the names of 5 movies whose soundtrack was composed by <composer>.
            """)
    .build();

String prompt = promptTemplate.render(Map.of("composer", "John Williams"));

    该类实现的接口支持提示词创建的不同方面：

    专注于创建和渲染提示字符串，代表了最基础的提示生成形式。

    专为通过生成和操纵对象来创建提示而设计。

    旨在返回对象，该对象可传递给以生成响应。

    尽管这些接口在许多项目中可能不会被广泛使用，但它们展示了提示词创建的不同方法。

    已实现的接口为

    public interface PromptTemplateStringActions {

	String render();

	String render(Map<String, Object> model);

}

    `String render()` 方法：将提示模板渲染为最终字符串格式，无需外部输入，适用于不包含占位符或动态内容的模板。

    `String render(Map model)` 方法：增强渲染功能以支持动态内容。该方法使用一个 `Map`，其中映射键为提示模板中的占位符名称，值是要插入的动态内容。

    public interface PromptTemplateMessageActions {

	Message createMessage();

    Message createMessage(List<Media> mediaList);

	Message createMessage(Map<String, Object> model);

}

    `Message createMessage()` 方法：创建一个不包含额外数据的 `Message` 对象，用于静态或预定义的消息内容。

    `Message createMessage(List mediaList)` 方法：创建一个包含静态文本和媒体内容的 `Message` 对象。

    `Message createMessage(Map model)` 方法：扩展消息创建功能以集成动态内容，接受一个 `Map`，其中每个条目代表消息模板中的占位符及其对应的动态值。

    public interface PromptTemplateActions extends PromptTemplateStringActions {

	Prompt create();

	Prompt create(ChatOptions modelOptions);

	Prompt create(Map<String, Object> model);

	Prompt create(Map<String, Object> model, ChatOptions modelOptions);

}

    `Prompt create()` 方法：在不依赖外部数据输入的情况下生成 `Prompt` 对象，适用于静态或预定义的提示。

    `Prompt create(ChatOptions modelOptions)` 方法：生成一个 `Prompt` 对象，无需外部数据输入，并针对聊天请求指定特定选项。

    `Prompt create(Map model)` 方法：将提示词创建能力扩展至包含动态内容，接收一个 `Map`，其中每个映射项代表提示词模板中的占位符及其关联的动态值。

    `Prompt create(Map model, ChatOptions modelOptions)` 方法：将提示词创建能力扩展至包含动态内容，接收一个 `Map`，其中每个映射项代表提示词模板中的占位符及其关联的动态值，以及针对聊天请求的具体选项。

    使用示例

    下面展示了一个取自提示模板 AI 工作坊的简单示例。

    PromptTemplate promptTemplate = new PromptTemplate("Tell me a {adjective} joke about {topic}");

Prompt prompt = promptTemplate.create(Map.of("adjective", adjective, "topic", topic));

return chatModel.call(prompt).getResult();

    下面展示了从角色 AI 研讨会中选取的另一个示例。

    String userText = """
    Tell me about three famous pirates from the Golden Age of Piracy and why they did.
    Write at least a sentence for each pirate.
    """;

Message userMessage = new UserMessage(userText);

String systemText = """
  You are a helpful AI assistant that helps people find information.
  Your name is {name}
  You should reply to the user's request with your name and also in the style of a {voice}.
  """;

SystemPromptTemplate systemPromptTemplate = new SystemPromptTemplate(systemText);
Message systemMessage = systemPromptTemplate.createMessage(Map.of("name", name, "voice", voice));

Prompt prompt = new Prompt(List.of(userMessage, systemMessage));

List<Generation> response = chatModel.call(prompt).getResults();

    这展示了如何使用 `SystemPromptTemplate` 构建 `Prompt>` 实例，通过传入占位符值创建一个带有系统角色的 `Message`。 随后，将角色为 `user` 的消息与角色为 `system` 的消息组合，形成最终的提示（prompt）。 最后，将该提示传递给 ChatModel 以获取生成式响应。

    使用自定义模板渲染器

    您可以通过实现TemplateRenderer接口并将其传递给PromptTemplate构造函数来使用自定义模板渲染器。您也可以继续使用默认的StTemplateRenderer，但使用自定义配置。

    默认情况下，模板变量由 {} 语法标识。如果您计划在提示词中包含 JSON，可能需要使用不同的语法以避免与 JSON 语法冲突。例如，您可以使用 < 和 > 作为分隔符。

    PromptTemplate promptTemplate = PromptTemplate.builder()
    .renderer(StTemplateRenderer.builder().startDelimiterToken('<').endDelimiterToken('>').build())
    .template("""
            Tell me the names of 5 movies whose soundtrack was composed by <composer>.
            """)
    .build();

String prompt = promptTemplate.render(Map.of("composer", "John Williams"));

    使用资源而非原始字符串

    Spring AI 支持 `org.springframework.core.io.Resource` 抽象，因此您可以将提示数据存储在文件中，并直接在 `PromptTemplate` 中使用。 例如，您可以在 Spring 管理的组件中定义一个字段来检索该 `Resource`。

    @Value("classpath:/prompts/system-message.st")
private Resource systemResource;

    然后将该资源直接传递给 `SystemPromptTemplate`。

    SystemPromptTemplate systemPromptTemplate = new SystemPromptTemplate(systemResource);

    提示工程

    在生成式人工智能中，提示词的设计是开发人员的一项关键任务。这些提示词的质量和结构会显著影响人工智能输出效果的好坏。投入时间和精力精心设计提示词，可以极大地提升人工智能的产出结果。

    在人工智能社区中，分享和讨论提示词是一种常见做法。这种协作方式不仅营造了共同学习的氛围，还促进了高效提示词的发现与应用。

    该领域的研究通常涉及分析并比较不同的提示，以评估其在各种情境下的有效性。例如，一项重要研究表明，在提示开头加入“深呼吸，然后逐步解决这个问题”能显著提高解决问题的效率。这凸显了精心选择的语言对生成式人工智能系统性能的影响。

    掌握提示词的最佳用法，尤其是在人工智能技术飞速发展的背景下，始终是一项持续的挑战。 您应认识到提示工程的重要性，并考虑借鉴社区和研究的见解，以优化提示词的创建策略。

    创建有效的提示

    在开发提示词时，整合几个关键要素对于确保其清晰度和有效性至关重要：

    • 说明：向人工智能提供清晰直接的指令，就像与人交流一样。这种清晰度对于帮助人工智能“理解”期望至关重要。

    • 外部背景：在必要时，请包含相关的背景信息或针对 AI 回复的具体指导。此“外部背景”用于界定提示词的范围，并帮助 AI 理解整体情境。

    • 用户输入：这是直截了当的部分——用户的直接请求或问题，构成了提示的核心。

    • 输出指示：这一方面可能颇具挑战性。它涉及指定 AI 响应所需的格式，例如 JSON。然而，请注意 AI 未必能始终严格遵循该格式。例如，它可能会在真正的 JSON 数据之前添加诸如“这是您的 JSON"之类的短语，或者有时生成看似 JSON 但结构不准确的伪 JSON 内容。

    为人工智能提供预期的问答格式示例，在构建提示词时非常有益。这种做法有助于人工智能“理解”您查询的结构和意图，从而产生更精确和相关的回答。虽然本文档并未深入探讨这些技术，但它们为人工智能提示工程领域的进一步探索提供了起点。

    以下为进一步调查的资源列表。

    简单技巧

    • 文本摘要：
      将冗长的文本精简为简洁的摘要，在保留关键要点和核心思想的同时，省略次要细节。

    • 问答：
      专注于根据用户提出的问题，从提供的文本中得出具体答案。其核心在于精准定位并提取与查询相关的信息。

    • 文本分类：
      系统地将文本划分为预定义的类别或组，通过分析文本内容并将其归入最合适的类别。

    • 对话：
      创建交互式对话，使 AI 能够与用户进行来回交流，模拟自然的对话流程。

    • 代码生成：
      根据特定的用户要求或描述生成功能性代码片段，将自然语言指令转换为可执行的代码。

    高级技巧

    • 零样本、少样本学习：
      使模型能够在几乎没有特定问题类型的先例情况下，做出准确的预测或响应，并通过已习得的泛化能力来理解并执行新任务。

    • 思维链：
      将多个 AI 响应链接起来，以创建连贯且具备上下文感知能力的对话。它有助于 AI 保持讨论的脉络，确保相关性和连续性。

    • ReAct（推理 + 行动）：
      在此方法中，AI 首先对输入进行分析（进行推理），然后确定最合适的行动方案或回应。它将理解与决策相结合。

    微软指导方针

    • 提示词创建与优化框架：
      微软提供了一套结构化的方法，用于开发和优化提示词。该框架指导用户创建能有效引发 AI 模型期望响应的提示词，从而优化交互的清晰度与效率。

    Tokens

    Token 是人工智能模型处理文本的核心要素，它充当桥梁，将人类理解的词汇转换为 AI 模型可处理的格式。 这一转换分为两个阶段：输入时将词汇转换为 Token，输出时再将 Token 还原为词汇。

    分词是将文本分解为词元的过程，这是人工智能模型理解和处理语言的基础。 人工智能模型利用这种分词格式来理解并响应提示。

    为了更好地理解 token，可以将其视为单词的片段。通常，一个 token 大约代表一个单词的四分之三。例如，莎士比亚的全部作品总字数约为 90 万词，换算成 token 则大约有 120 万个。

    尝试使用OpenAI 分词器界面，查看单词是如何被转换为 token 的。

    Token 不仅具有技术层面的意义，在人工智能处理中扮演着关键角色，其实际影响还延伸至计费模式和模型能力等方面：

    • 计费：AI 模型服务通常按 Token 使用量计费。输入（提示词）和输出（响应）均计入总 Token 数量，因此更短的提示词更具成本效益。

    • 模型限制：不同的 AI 模型具有不同的令牌（token）限制，这定义了它们的“上下文窗口”——即它们一次能够处理的最大信息量。例如，GPT-3 的限制为 4K 个令牌，而像 Claude 2 和 Meta Llama 2 等其他模型的限制为 100K 个令牌，某些研究模型甚至可以处理高达 100 万个令牌。

    • 上下文窗口：模型的令牌限制决定了其上下文窗口的大小。超出此限制的输入不会被模型处理。因此，发送用于处理的最小有效信息集至关重要。例如，在询问《哈姆雷特》时，无需包含莎士比亚其他作品中的令牌。

    • 响应元数据：AI 模型响应的元数据包括所使用的 token 数量，这是管理使用量和成本的关键信息。
