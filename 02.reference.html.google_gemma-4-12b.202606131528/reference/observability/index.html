    • 可观测性

    Observability

    Spring AI 基于 Spring 生态系统中的可观测性功能，提供对 AI 相关操作的深入洞察。它为其核心组件提供指标和追踪能力，这些组件包括：ChatClient（包括 Advisor）、ChatModel、EmbeddingModel、ImageModel 和 VectorStore。

    请参阅 Spring Boot Metrics 和 Spring Boot Tracing 文档，以在您的应用程序中启用指标和追踪支持。

    低基数键将添加到指标（metrics）和追踪（traces）中，而高基数键仅会添加到追踪（traces）中。

    聊天客户端

    当调用 ChatClient 的 call() 或 stream() 操作时，会记录 spring.ai.chat.client 观测数据。 它们测量执行调用的耗时并传播相关的链路追踪信息。

    表 1. 低基数键
    Name Description

    gen_ai.operation.name

    Always framework.

    gen_ai.system

    Always spring_ai.

    spring.ai.chat.client.stream

    聊天模型响应是流式传输吗 - true 或 false

    spring.ai.kind

    Spring AI 中的框架 API 类型：chat_client。
    表 2. 高基数键

    Name

    Description

    spring.ai.chat.client.advisors

    已配置的聊天客户端顾问列表。

    spring.ai.chat.client.conversation.id

    使用聊天记忆时的会话标识符。

    spring.ai.chat.client.tool.names

    传递给聊天客户端的工具名称。

    提示词与补全数据

    ChatClient 的提示词（prompt）和补全数据通常体积庞大，且可能包含敏感信息。 出于这些原因，默认情况下不会导出这些数据。

    Spring AI 支持记录提示词（prompt）和生成内容（completion）数据，以辅助调试和故障排除。

    Property Description Default

    spring.ai.chat.client.observations.log-prompt

    是否记录聊天客户端的提示内容。

    false

    spring.ai.chat.client.observations.log-completion

    是否记录聊天客户端的完成内容。

    false
    如果您启用聊天客户端提示词（prompt）和补全（completion）数据的日志记录，可能会存在泄露敏感或私密信息的风险。请务必小心！

    spring.ai.kind

    Spring AI 中的框架 API 类型：advisor。

    聊天模型

    OpenAI 和 Anthropic 的聊天模型都会发出 HTTP 层观测数据（聊天模型层 + HTTP 层），但在流式调用方面有一个特定的限制。 HTTP 层观测数据包含 HTTP 方法、URI、状态码，并会在传输过程中传播 traceparent 到下游服务（AI 网关、代理、兼容 OpenAI 的推理服务器）。

    对于同步调用，okhttp.requests span 正确嵌套在 gen_ai.client.operation span 下。 对于流式调用，HTTP span 已被记录，但并未被父级关联到 chat-model span 下——SDK 的异步流式路径在调用 Spring AI 的 HTTP 客户端之前会跳转到 ForkJoinPool.commonPool()，从而在那个边界处丢失了调用线程的观测上下文。

    请参阅 OpenAI chat 文档 和 Anthropic chat 文档 以获取详情。

    在调用 ChatModel 的 call 或 stream 方法时，会记录 gen_ai.client.operation 观测值。 它们测量方法完成所花费的时间，并传播相关的追踪信息。

    指标用于衡量单次模型调用所使用的输入和输出 token 数量。

    聊天提示词与完成数据

    聊天提示词和补全数据通常体积庞大，且可能包含敏感信息。 出于这些原因，默认情况下不会导出这些数据。

    Spring AI 支持记录聊天提示词（prompt）和完成内容（completion）数据，这在故障排除场景中非常有用。当可用于追踪时，日志将包含追踪信息以便更好地进行关联。

    Property Description Default

    spring.ai.chat.observations.log-prompt

    记录提示词内容。true 或 false

    false

    spring.ai.chat.observations.log-completion

    记录完成内容。true 或 false

    false

    spring.ai.chat.observations.include-error-logging

    在观测中包含错误日志。true 或 false

    false
    如果您启用聊天提示词和完成数据的日志记录，可能会有泄露敏感或私密信息的风险。请务必小心！

    工具调用

    在聊天模型交互的上下文中执行工具调用时，会记录 spring.ai.tool 观测值。它们用于衡量工具调用完成所花费的时间，并传播相关的追踪信息。

    Name Description

    gen_ai.operation.name

    正在执行的操作名称。它始终是 execute_tool>。

    gen_ai.system

    负责操作的提供商。它始终是 spring_ai。

    spring.ai.kind

    Spring AI 执行的操作类型。它始终是 tool_call。

    spring.ai.tool.definition.name

    工具的名称。

    spring.ai.tool.type

    工具的类型。默认值为 function。
    表 8. 高基数键

    Name

    Description

    spring.ai.tool.definition.description

    工具描述。

    spring.ai.tool.definition.schema

    调用该工具所使用的参数架构。

    spring.ai.tool.call.id

    由聊天模型识别的工具调用 ID。

    spring.ai.tool.call.arguments

    工具调用的输入参数。（仅在启用时）

    spring.ai.tool.call.result

    工具调用执行的结果。（仅在启用时）

    工具调用参数与结果数据

    工具调用的输入参数和结果默认不会被导出，因为它们可能包含敏感信息。

    Spring AI 支持将工具调用参数和结果数据导出为 span 属性。

    Property Description Default

    spring.ai.tools.observations.include-content

    在观察中包含工具调用内容。true 或 false

    false
    如果您启用在观测结果中包含工具调用参数和结果，可能会存在泄露敏感或私有信息的风险。请务必小心！

    向量数据库

    更多指标参考

    本章节记录了 Spring AI 组件在 Prometheus 中显示的各项指标。

    指标命名规范

    Spring AI 使用 Micrometer。基础指标名称使用点号（例如，gen_ai.client.operation），而 Prometheus 在导出时会将其转换为下划线并加上标准后缀：

    • 计时器 → <base>_seconds_count、<base>_seconds_sum、<base>_seconds_max 以及（如果支持）<base>_active_count

    • Counters → <base>_total (monotonic)

    以下展示了基础指标名称如何扩展为 Prometheus 时间序列。

    基础指标名称 导出的时间序列

    gen_ai.client.operation

    gen_ai_client_operation_seconds_count
    gen_ai_client_operation_seconds_sum
    gen_ai_client_operation_seconds_max
    gen_ai_client_operation_active_count

    db.vector.client.operation

    db_vector_client_operation_seconds_count
    db_vector_client_operation_seconds_sum
    db_vector_client_operation_seconds_max
    db_vector_client_operation_active_count

    理解“进行中”与“已完成”的区别

    • Active (*_active_count) —— 当前正在进行的任务（并发量/负载）的瞬时指标。

    • 已完成 (*_seconds_sum|count|max) —— 已完成操作的统计数据：

    • _seconds_sum / _seconds_count → 平均延迟

    • _seconds_max → 自上次抓取以来的高水位线（取决于注册表行为）
