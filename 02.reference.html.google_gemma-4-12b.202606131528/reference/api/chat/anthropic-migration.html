    将 Anthropic 模块迁移至官方 Java SDK

    在 2.0.0-M3 版本中，spring-ai-anthropic 基于官方的 com.anthropic:anthropic-java SDK 进行了重写，取代了之前手动编写的 RestClient / WebClient 实现。之前的 AnthropicApi 类是一个包含 47 个嵌套 DTO record 的 2,300 行文件。

    新模块是建立在 SDK 之上的薄适配层，而非并行的 API。Spring AI 的价值在于其自身的抽象——ChatModel、ChatClient、advisors、observability 和 auto-config——以及跨提供商通用的功能。在 SDK 已经涵盖某些功能（如 cache-control 建模、流式传输、速率限制处理）的地方，我们去掉了之前的模块中的包装器，而不是沿用它，因此应用程序直接使用 SDK 的类型。这样做可以保持接口面积精简，并避免在 Anthropic 发布新 SDK 版本时出现偏差。

    Maven 坐标、spring-ai-starter-model-anthropic Boot starter 以及 spring.ai.anthropic.* 配置属性均保持不变。 ChatClient API 保持不变。 ChatModel.call(Prompt) 和 ChatModel.stream(Prompt) 保留其签名。 AnthropicChatOptions 保留所有现有字段，并新增了用于技能、网络搜索、服务层级、推理地理位置和结构化输出的字段。

    变更内容

    Area Change

    AnthropicChatModel construction

    公共构造函数已移除。请使用 AnthropicChatModel.builder()。

    org.springframework.ai.anthropic.api.AnthropicApi 及其嵌套的 DTOs

    已移除。如需直接访问 API，请使用 SDK 中的 com.anthropic.client.AnthropicClient。

    AnthropicCacheOptions, AnthropicCacheStrategy, AnthropicCacheTtl, CacheBreakpointTracker, CacheEligibilityResolver

    从 org.springframework.ai.anthropic.api（以及 api.utils）移动到根包 org.springframework.ai.anthropic。枚举值保持不变。

    CitationDocument

    重命名为 AnthropicCitationDocument。

    AnthropicCacheType, StreamHelper, metadata.AnthropicRateLimit

    已移除，未直接替换。

    Default maxTokens

    从 500 更改为 4096。

    Transitive com.squareup.okhttp3:okhttp

    新增，由 com.anthropic:anthropic-java 拉取。

    如果您仅使用 ChatClient 或 ChatModel

    如果您的代码如下所示，则不需要进行迁移：

    @Autowired ChatClient.Builder builder;

String response = builder.build()
    .prompt("Tell me a joke")
    .call()
    .content();

    自动配置会生成一个连接到基于新 SDK 实现的 AnthropicChatModel 豆（bean）。调用代码不受影响。

    需要注意的一个行为变化是新的默认 maxTokens 值（参见 默认 maxTokens 现在为 4096）。

    如果您通过编程方式构建 AnthropicChatModel

    请使用 builder 替换直接调用构造函数：

    // Before
AnthropicApi anthropicApi = new AnthropicApi(apiKey);
AnthropicChatModel chatModel = new AnthropicChatModel(anthropicApi,
    AnthropicChatOptions.builder().model("claude-haiku-4-5").maxTokens(2048).build(),
    retryTemplate,
    toolCallingManager);

// After
AnthropicChatModel chatModel = AnthropicChatModel.builder()
    .apiKey(apiKey)
    .defaultOptions(AnthropicChatOptions.builder()
        .model("claude-haiku-4-5")
        .maxTokens(2048)
        .build())
    .toolCallingManager(toolCallingManager)
    .build();

    构建器还接受 baseUrl、timeout、maxRetries、proxy、customHeaders、observationRegistry 和 observationConvention。 没有 retryTemplate 构建方法；重试现在由 SDK 处理（参见 Retry uses SDK maxRetries, not RetryTemplate）。

    如果您导入了缓存或引用类型

    缓存和引用辅助类已从 api（以及 api.utils）子包移动到根 org.springframework.ai.anthropic 包中。 请按如下方式更新导入：

    旧导入 新导入

    org.springframework.ai.anthropic.api.AnthropicCacheOptions

    org.springframework.ai.anthropic.AnthropicCacheOptions

    org.springframework.ai.anthropic.api.AnthropicCacheStrategy

    org.springframework.ai.anthropic.AnthropicCacheStrategy

    org.springframework.ai.anthropic.api.AnthropicCacheTtl

    org.springframework.ai.anthropic.AnthropicCacheTtl

    org.springframework.ai.anthropic.api.utils.CacheBreakpointTracker

    org.springframework.ai.anthropic.CacheBreakpointTracker

    org.springframework.ai.anthropic.api.utils.CacheEligibilityResolver

    org.springframework.ai.anthropic.CacheEligibilityResolver

    org.springframework.ai.anthropic.api.CitationDocument

    org.springframework.ai.anthropic.AnthropicCitationDocument

    AnthropicCacheStrategy 的枚举值（NONE、TOOLS_ONLY、SYSTEM_ONLY、SYSTEM_AND_TOOLS、CONVERSATION_HISTORY）和 AnthropicCacheTtl（FIVE_MINUTES、ONE_HOUR）保持不变。 重命名后的 AnthropicCitationDocument 上仍保留有 plainText(…​)、pdf(…​) 和 customContent(…​) 工厂方法。

    如果您直接使用了 AnthropicApi

    AnthropicApi、其嵌套的 DTO records 以及 AnthropicCacheType 已被移除。在寻求使用 SDK 客户端之前，请考虑 AnthropicChatModel 是否涵盖了你正在执行的操作。通常情况下它是涵盖的，而且你可以保留框架集成。

    AnthropicChatModel 在原始的 AnthropicClient 之上增加了以下功能：

    • 提供商中立的请求和响应类型（Prompt、ChatResponse、Generation、Usage），因此应用程序代码不会依赖于 com.anthropic.*。

    • 与 ToolCallback 和 ToolCallingManager 循环集成的工具调用，包括自动多轮执行。

    • 以 Reactor 形式流式传输 Flux<ChatResponse>，而非使用 SDK 基于回调的 AsyncStreamResponse。

    • 带有策略建模、TTL 控制和 4 个断点强制执行的 Prompt 缓存（AnthropicCacheOptions）。

    • 在 ChatResponseMetadata 下出现了带有四个位置变体的 Citation。

    • Skills、内置网络搜索、服务层级、推理地理位置以及结构化输出作为 AnthropicChatOptions 字段，均可从 spring.ai.anthropic.chat.* 进行绑定。

    • Spring Boot 自动配置与 Micrometer 观测。

    • 位于模型上方的 ChatClient 流水线（包含 advisors、消息模板、RAG、对话记忆和结构化输出转换器）。

    • 提供商可移植性：相同的 ChatClient 代码可运行在 OpenAI、Bedrock、Google GenAI 等平台。

    对于典型的聊天用法，请切换到 AnthropicChatModel.builder()（参见 如果您以编程方式构建 AnthropicChatModel）：

    // Before
AnthropicApi api = new AnthropicApi(apiKey);
AnthropicApi.ChatCompletionRequest req = new AnthropicApi.ChatCompletionRequest(
    AnthropicApi.ChatModel.CLAUDE_HAIKU_4_5.getValue(),
    List.of(new AnthropicApi.AnthropicMessage(List.of(new AnthropicApi.ContentBlock("hello")), AnthropicApi.Role.USER)),
    null, 1024, null, 0.7, null, null, null, null, false);
ResponseEntity<AnthropicApi.ChatCompletionResponse> resp = api.chatCompletionEntity(req);

// After
AnthropicChatModel chatModel = AnthropicChatModel.builder()
    .apiKey(apiKey)
    .defaultOptions(AnthropicChatOptions.builder()
        .model("claude-haiku-4-5")
        .maxTokens(1024)
        .temperature(0.7)
        .build())
    .build();
ChatResponse response = chatModel.call(new Prompt("hello"));

    如果你确实需要 AnthropicChatModel 未提供的 Anthropic API 接口（例如 beta 端点、files API 或自定义技能的 CRUD 操作），请直接使用 SDK 客户端。到那时，你已经脱离了框架——将失去可观测性、供应商中立性以及 ChatClient 流水线：

    import com.anthropic.client.AnthropicClient;
import com.anthropic.client.okhttp.AnthropicOkHttpClient;
import com.anthropic.models.messages.MessageCreateParams;
import com.anthropic.models.messages.Model;

AnthropicClient client = AnthropicOkHttpClient.builder().apiKey(apiKey).build();
MessageCreateParams params = MessageCreateParams.builder()
    .model(Model.CLAUDE_HAIKU_4_5)
    .maxTokens(1024)
    .temperature(0.7)
    .addUserMessage("hello")
    .build();
com.anthropic.models.messages.Message message = client.messages().create(params);

    手工滚动的记录类型在 SDK 的 com.anthropic.models.messages.* 下有直接对应的类：

    移除的类型（旧版 AnthropicApi.*） SDK 替换项（com.anthropic.models.messages.*）

    ChatCompletionRequest

    MessageCreateParams

    ChatCompletionResponse

    Message

    AnthropicMessage

    MessageParam

    ContentBlock

    ContentBlock（密封联合类型：TextBlock、ToolUseBlock、ThinkingBlock、RedactedThinkingBlock、ServerToolUseBlock、WebSearchToolResultBlock、ContainerUploadBlock，……）

    Tool

    Tool

    ToolChoiceAuto / ToolChoiceAny / ToolChoiceTool / ToolChoiceNone

    ToolChoice（密封联合类型，包含 ToolChoiceAuto、ToolChoiceAny、ToolChoiceTool 和 ToolChoiceNone 变体）

    来源（图像 / PDF 媒体）

    Base64ImageSource, UrlImageSource, Base64PdfSource, UrlPdfSource

    MessageStartEvent, ContentBlockStartEvent, ContentBlockDeltaEvent, MessageDeltaEvent, …​

    RawMessageStreamEvent（密封联合类型）
    ToolUseBlock.input() 返回的是 SDK 的 JsonValue，而不是 JSON 字符串。对 JsonValue 调用 .toString() 会产生 Java map 语法（{key=value}），它看起来像 JSON 但并不是。请使用 JsonValue.Visitor<T> 进行遍历，或通过 Jackson 进行序列化以获取真实的 JSON 字符串。

    已移除，改用 SDK 等效项

    这些类型已被移除，因为 SDK 已经暴露了相同的概念。请直接使用 SDK 类型。

    已移除 改用

    org.springframework.ai.anthropic.api.AnthropicCacheType

    com.anthropic.models.messages.CacheControlEphemeral。旧的枚举仅包含字面量 ephemeral 值，这也是 API 支持的唯一缓存控制类型。

    org.springframework.ai.anthropic.api.StreamHelper

    com.anthropic.core.http.AsyncStreamResponse<RawMessageStreamEvent>。StreamHelper 是旧版 WebClient 流式传输路径中的内部 SSE 合并辅助类；现在的 SDK 原生提供流事件，并且 Spring AI 在内部将其桥接到 Reactor Flux。调用 ChatModel.stream(Prompt) 的代码不受影响。

    org.springframework.ai.anthropic.metadata.AnthropicRateLimit

    com.anthropic.errors.RateLimitException（在重试耗尽后由 SDK 抛出），以及 SDK 响应对象上的 header。将读取 ChatResponseMetadata 中速率限制元数据的代码替换为异常处理。

    行为变更

    提示词级选项不再与模型默认值合并

    之前的模块通过 ModelOptionsUtils.copyToTarget(…​) 和 ModelOptionsUtils.merge(…​) 将提示词层级的 AnthropicChatOptions 合并到了模型层级的默认值中，因此 model、temperature 以及任何其他未设置的字段都从模型的默认值中填充：

    // Before: only maxTokens set; model + temperature inherited from defaults.
Prompt prompt = new Prompt(
    "Tell me a joke",
    AnthropicChatOptions.builder().maxTokens(2048).build());
chatModel.call(prompt);

    新模块无法合并。 直接使用提示词级选项实例；如果提示词中没有选项，则使用模型默认值。

    // After: prompt-level options must be "full", or null.
Prompt prompt = new Prompt(
    "Tell me a joke",
    chatModel.getOptions().mutate().maxTokens(2048).build());
chatModel.call(prompt);

    这是针对更广泛的变更 升级到 2.0.0-M5 — ChatOptions 处理 的前置移植，并为 Anthropic 提前发布。 ChatClient 在到达模型之前会执行自身的合并操作，因此使用 ChatClient 的调用者不受影响。

    默认 maxTokens 现在为 4096

    AnthropicChatOptions 将 maxTokens 的默认值从 500 修改为 4096。 之前的默认值经常导致响应被截断；新的数值与其他的 Spring AI 对话模块保持一致。

    如果您依赖 500 来限制成本，请将其显式设置：

    spring.ai.anthropic.chat.max-tokens=500

    重试使用 SDK 中的 maxRetries，而非 RetryTemplate

    之前的模块在其构造函数中接收一个 Spring Retry RetryTemplate。 现在重试由 SDK 处理，并通过 maxRetries（默认值为 2）进行配置：

    spring.ai.anthropic.max-retries=5

    任何专门为 Anthropic 模块配置的 RetryTemplate bean 都可以被移除。 为了更精细的控制，可以通过自定义的 AnthropicSetup 来配置 SDK 客户端。

    流式思考事件

    有两个变化会影响任何订阅原始 Flux<ChatResponse> 流（而不是让 ChatClient 或 MessageAggregator 对其进行折叠）的人。

    之前的模块将思考块的文本和签名捆绑到单个 Generation 中。SDK 将它们作为独立的事件传递，而新模块也按此方式转发：在思考文本增量（deltas）之后、后续任何文本增量之前，会到达一个带有 properties.signature 的 Generation。MessageAggregator 和 `ChatClient` 内置的聚合功能会透明地吸收这个额外的块。

    Thinking-text deltas 现在也包含 properties.thinking = Boolean.TRUE。之前的模块将其作为纯文本输出，导致调用者在流式传输过程中无法可靠地区分思考文本和响应文本。

    完整的流媒体元数据键：

    Block Generation carries

    思考文本增量

    content = <thinking text>，properties.thinking = true（M3 新增）

    思考签名增量

    empty content, properties.signature = <signature>

    已删除思考块

    empty content, properties.data = <data>

    同步思考块（非流式）

    content = <thinking text>, properties.signature = <signature> (single Generation)

    Prompt 缓存变更

    如果您配置了 AnthropicCacheOptions，需要了解的三个行为：

    • 4 个断点限制是在 Spring AI 中强制执行的，而不是在 API 端。 Anthropic 每个请求最多允许 4 个缓存断点。之前的模块只是透传标记，让 API 拒绝超出数量的部分。现在的 CacheBreakpointTracker 会进行计数，并静默跳过超过 4 个的添加操作，同时记录一次性的 WARN 日志。最容易达到上限的情况是 SYSTEM_AND_TOOLS 结合多块系统缓存和引用文档。以前因 API 错误而失败的请求现在可以以减少的缓存量成功运行，因此请在升级后检查您的缓存命中率。

    • AnthropicCacheStrategy.NONE 意味着“未设置”，而非“禁用”。在 prompt 层级设置 NONE 将会回退到模型的默认值。如果模型默认开启了缓存，而您想将其关闭，请构建第二个 AnthropicChatModel，并将 AnthropicCacheOptions.disabled() 作为其默认值。

    • 工具缓存的 TTL 取自 MessageType.SYSTEM。 无论采用何种策略，resolveToolCacheControl 都会查找 messageTypeTtl(MessageType.SYSTEM)。设置 messageTypeTtl(MessageType.USER, ONE_HOUR) 对工具缓存没有影响。

    引用文档的一致性在客户端进行验证

    Anthropic API 要求在单个请求中，所有包含引用配置的 DocumentBlockParam 必须共享相同的 citations.enabled 值。 AnthropicChatOptions.validateCitationConsistency() 现在会强制执行此项规定，并在请求发送前抛出 IllegalArgumentException。之前的模块则允许 API 返回 HTTP 400。 混合使用已启用和未启用引用的文档的测试或调用点现在将在构建时失败，而不是在网络调用时失败。

    新的 OkHttp 传递依赖

    com.anthropic:anthropic-java 会引入 com.squareup.okhttp3:okhttp。 大多数应用程序不会受到影响；如果您有严格的依赖收敛规则或现有的 OkHttp 版本锁定，您可能需要添加一个 <dependencyManagement> 条目。

    新功能

    此次迁移还启用了多个 Anthropic 功能。请参阅 Anthropic Chat 获取完整参考。

    • 原生技能（AnthropicSkill，AnthropicSkillContainer）。

    • 内置网络搜索工具（AnthropicWebSearchTool）。

    • 服务层级选择（AnthropicServiceTier）。

    • 用于数据驻留的推理地理位置（us，eu）。

    • 通过 JsonOutputFormat 和 Effort 实现原生结构化输出（需要 claude-sonnet-4-6 或更高版本）。

    • 扩展思考显示模式（已摘要/省略）。

    • Citation 类型包含四种位置变体（CHAR_LOCATION、PAGE_LOCATION、CONTENT_BLOCK_LOCATION、WEB_SEARCH_RESULT_LOCATION）。

    • AnthropicChatOptions#httpHeaders 上的单次请求 HTTP 请求头，与 AbstractAnthropicOptions 上的客户端级 customHeaders 不同。customHeaders 在客户端上设置一次并应用于每次请求；httpHeaders 在每个 Prompt 中设置并在请求构建时合并。适用于请求追踪、beta-API 开关和路由。

    静默失败的内容

    编译错误很容易处理。这些不会抛出异常；它们而是产生不同的输出。

    • 部分提示词级选项。 new Prompt(text, AnthropicChatOptions.builder().maxTokens(2048).build()) 不再继承模型默认设置中的 model、temperature 等参数（参见 提示词级选项不再与模型默认值合并）。不会出现编译错误或异常；请求将以不同的值运行。如果升级后输出发生偏移且您直接调用了 ChatModel，请首先查看此处。

    • 如果升级后成本上升，请检查您是否依赖旧的 500 token maxTokens 默认值来限制响应。

    • 缓存断点已超过四个。通过将多块系统缓存与工具和引用文档堆叠，可以突破 Anthropic 的 4 个断点上限。CacheBreakpointTracker 会跳过额外的断点并仅记录一次 WARN。缓存命中率会下降，但不会报错。

    • 升级后，大部分编译错误源于过时的 org.springframework.ai.anthropic.api.AnthropicCache* 导入。通过项目范围内的查找并替换即可修复这些问题。
