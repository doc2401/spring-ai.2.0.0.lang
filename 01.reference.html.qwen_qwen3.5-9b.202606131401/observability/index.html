    Observability

    Spring AI 基于 Spring 生态系统中的可观测性功能，为 AI 相关操作提供洞察。它为以下核心组件提供了指标和追踪能力：ChatClient（包括Advisor）、ChatModel、EmbeddingModel、ImageModel以及VectorStore。

    参考 Spring Boot 指标 和 Spring Boot 追踪 文档，以在您的应用程序中启用指标和追踪支持。

    低基数键将添加到指标和追踪中，而高基数键仅添加到追踪中。

    聊天客户端

    当调用 ChatClient 的 `call()` 或 `stream()` 操作时，会记录 `spring.ai.chat.client` 观测数据。这些观测数据用于衡量执行调用所花费的时间，并传播相关的追踪信息。

    表 1。低基数键
    Name Description

    gen_ai.operation.name

    Always framework.

    gen_ai.system

    Always spring_ai.

    spring.ai.chat.client.stream

    聊天模型响应是否为流式输出——true 或 false

    spring.ai.kind

    Spring AI 中的框架 API 类型为：chat_client。
    表 2。高基数键

    Name

    Description

    spring.ai.chat.client.advisors

    已配置的聊天客户端顾问列表。

    spring.ai.chat.client.conversation.id

    使用聊天记忆时的会话标识符。

    spring.ai.chat.client.tool.names

    传递给聊天客户端的工具名称。

    提示词与完成数据

    `ChatClient` 的提示词和完成数据通常体积较大，且可能包含敏感信息。 因此，这些数据默认不会被导出。

    Spring AI 支持记录提示词和完成数据，以帮助调试和故障排除。

    Property Description Default

    spring.ai.chat.client.observations.log-prompt

    是否记录聊天客户端的提示内容。

    false

    spring.ai.chat.client.observations.log-completion

    是否记录聊天客户端的完成内容。

    false
    如果启用聊天客户端提示词和完成数据的日志记录，可能会泄露敏感或私人信息。请谨慎操作！

    聊天客户端顾问

    当执行顾问时，会记录 `spring.ai.advisor` 观测数据。这些观测数据用于衡量在顾问中花费的时间（包括在内层顾问中花费的时间），并传播相关的追踪信息。

    表 3。低基数键
    Name Description

    gen_ai.operation.name

    Always framework.

    gen_ai.system

    Always spring_ai.

    spring.ai.advisor.name

    顾问姓名。

    spring.ai.kind

    Spring AI 中的框架 API 类型：advisor。
    表 4。高基数键
    Name Description

    spring.ai.advisor.order

    顾问链中的顾问指令。

    对话模型

    OpenAI 和 Anthropic 的聊天模型均会发出 HTTP 层观测数据（包含聊天模型层 + HTTP 层），但流式调用存在一项特定限制。HTTP 层观测数据包含 HTTP 方法、URI 和状态码，并通过网络将 traceparent 传播至下游服务（AI 网关、代理服务器、兼容 OpenAI 的推理服务器）。

    对于同步调用，`okhttp.requests` 跨度正确嵌套在 `gen_ai.client.operation` 跨度之下。 对于流式调用，HTTP 跨度会被记录，但不会作为 chat-model 跨度的子跨度——SDK 的异步流式路径会在调用 Spring AI 的 HTTP 客户端之前跳转到 `ForkJoinPool.commonPool()`，从而在该边界处丢失了调用线程的观察上下文。

    有关详细信息，请参阅OpenAI 聊天文档和Anthropic 聊天文档。

    gen_ai.client.operation 观测会在调用 ChatModel 的 call 或 stream 方法时记录。它们衡量方法完成所花费的时间，并传播相关的追踪信息。

    gen_ai.client.token.usage 指标用于衡量单个模型调用所使用的输入和输出 token 数量。

    Name Description

    gen_ai.operation.name

    执行的操作名称。

    gen_ai.system

    由客户端仪器标识的模型提供商。

    gen_ai.request.model

    请求所针对的模型名称。

    gen_ai.response.model

    生成该回复的模型名称。

    gen_ai.request.max_tokens

    gen_ai.request.presence_penalty

    gen_ai.request.stop_sequences

    模型将用于停止生成更多 token 的序列列表。

    gen_ai.request.stream

    是否为流式模式发起的请求。仅在为 true 时显示。

    gen_ai.request.temperature

    模型请求的温度设置。

    gen_ai.request.top_k

    模型请求中的 top_k 采样设置。

    gen_ai.request.top_p

    gen_ai.response.finish_reasons

    gen_ai.response.id

    gen_ai.usage.cache_read.input_tokens

    gen_ai.usage.input_tokens

    gen_ai.usage.output_tokens

    模型输出（补全）中使用的 token 数量。

    gen_ai.usage.total_tokens

    请求中提供给模型的工具体义列表。

    聊天提示词与补全数据

    聊天提示词和完成数据通常体积庞大，且可能包含敏感信息。 因此，这些数据默认不会导出。

    Spring AI 支持记录聊天提示词和完成数据，适用于故障排查场景。当启用追踪时，日志将包含追踪信息，以便更好地进行关联分析。

    Property Description Default

    spring.ai.chat.observations.log-prompt

    记录提示内容。true 或 false

    false

    spring.ai.chat.observations.log-completion

    记录完成内容。true 或 false

    false

    spring.ai.chat.observations.include-error-logging

    在观察中启用错误日志记录。true 或 false

    false
    如果启用聊天提示词和完成数据的日志记录，可能会泄露敏感或私人信息。请谨慎操作！

    工具调用

    在聊天模型交互过程中执行工具调用时，会记录 `spring.ai.tool` 观测值。这些观测值用于衡量工具调用的耗时，并传播相关的追踪信息。

    表 7. 低基数键
    Name Description

    gen_ai.operation.name

    操作名称。它始终为 `execute_tool`。

    gen_ai.system

    负责操作的提供者。它始终为 `spring_ai`。

    spring.ai.kind

    Spring AI 执行的操作类型。它始终是 `tool_call`》。

    spring.ai.tool.definition.name

    工具名称。

    spring.ai.tool.type

    工具的类型。默认为 `function`。
    表 8。高基数键

    Name

    Description

    spring.ai.tool.definition.description

    工具描述。

    spring.ai.tool.definition.schema

    调用工具时所使用的参数模式。

    spring.ai.tool.call.id

    由聊天模型识别的工具调用 ID。

    spring.ai.tool.call.arguments

    工具调用的输入参数。（仅在启用时显示）

    spring.ai.tool.call.result

    工具调用执行的结果。（仅当启用时显示）

    工具调用参数与结果数据

    工具调用的输入参数和结果默认不会导出，因为它们可能包含敏感信息。

    Spring AI 支持将工具调用参数和结果数据导出为 Span 属性。

    Property Description Default

    spring.ai.tools.observations.include-content

    在观察中包括工具调用内容。true 或 false

    false
    如果在观察结果中包含工具调用参数和结果，可能会泄露敏感或私人信息。请小心！

    向量存储

    Spring AI 中的所有向量存储实现均已通过 Micrometer 进行配置，以提供指标和分布式追踪数据。

    `db.vector.client.operation` 观测值在交互向量存储时会被记录。它们测量了 `query`、`add` 和 `remove` 操作所花费的时间，并传播相关的追踪信息。

    表 13. 低基数键
    Name Description

    db.operation.name

    执行的操作或命令名称。为 `add`、delete 或 query 之一。

    db.system

    客户端仪表所标识的数据库管理系统（DBMS）产品。其中包括：pg_vector、azure、cassandra、chroma、elasticsearch、milvus、neo4j、opensearch、qdrant、redis、typesense、weaviate、pinecone、oracle、mongodb、gemfire 和 simple。

    spring.ai.kind

    Spring AI 中的框架 API 类型为：vector_store。
    表 14. 高基数键
    Name Description

    db.collection.name

    数据库中集合（表、容器）的名称。

    db.namespace

    数据库名称，包含服务器地址和端口的完整限定名。

    db.search.similarity_metric

    相似度搜索中使用的度量标准。

    db.vector.dimension_count

    向量的维度。

    db.vector.field_name

    向量中的名称字段（例如字段名）。

    db.vector.query.content

    正在执行的搜索查询内容。

    db.vector.query.filter

    搜索查询中使用的元数据过滤器。

    db.vector.query.response.documents

    相似搜索查询返回的文档。可选。

    db.vector.query.similarity_threshold

    接受所有搜索分数的相似度阈值。阈值为 0.0 表示接受任何相似度或禁用相似度阈值过滤。阈值为 1.0 表示需要完全匹配。

    db.vector.query.top_k

    查询返回的相似度最高的前 k 个向量。

    更多指标参考

    本节记录了 Spring AI 组件在 Prometheus 中发出的指标。

    指标命名规范

    Spring AI 使用 Micrometer。基础指标名称使用点号（例如 `gen_ai.client.operation`），而 Prometheus 将其导出时使用下划线和标准后缀：

    • 计时器 → <base>_seconds_count、<base>_seconds_sum、<base>_seconds_max，以及（如受支持）<base>_active_count

    • Counters → <base>_total (monotonic)

    下图展示了基础指标名称如何扩展为 Prometheus 时间序列。

    基础指标名称 导出的时间序列

    gen_ai.client.operation

    gen_ai_client_operation_seconds_count
    gen_ai_client_operation_seconds_sum
    gen_ai_client_operation_seconds_max
    gen_ai_client_operation_active_count

    db.vector.client.operation

    db_vector_client_operation_seconds_count
    db_vector_client_operation_seconds_sum
    db_vector_client_operation_seconds_max
    db_vector_client_operation_active_count

    理解活跃与已完成状态的区别

    • 活跃（*_active_count）——正在执行操作的瞬时指标（并发/负载）。

    • 已完成 (*_seconds_sum|count|max)——针对已完成的操作的统计信息：

    • _seconds_sum / _seconds_count → 平均延迟

    • _seconds_max → 自上次抓取以来的最高水位线（受注册表行为影响）
