    顾问 API

    Spring AI Advisors API 提供了一种灵活而强大的方式，用于拦截、修改并增强您 Spring 应用中的 AI 驱动交互。通过利用 Advisors API，开发人员可以创建更加复杂、可复用且易于维护的 AI 组件。

    主要优势包括封装重复的生成式人工智能模式、转换发送至和来自大型语言模型（LLM）的数据，并提供跨多种模型和使用场景的可移植性。

    您可以使用ChatClient API配置现有的顾问，示例如下：

    ChatMemory chatMemory = ... // Initialize your chat memory store
VectorStore vectorStore = ... // Initialize your vector store

var chatClient = ChatClient.builder(chatModel)
    .defaultAdvisors(
        MessageChatMemoryAdvisor.builder(chatMemory).build(), // chat-memory advisor
        QuestionAnswerAdvisor.builder(vectorStore).build()    // RAG advisor
    )
    .build();

var conversationId = "678";

String response = this.chatClient.prompt()
    // Set advisor parameters at runtime
    .advisors(advisor -> advisor.param(ChatMemory.CONVERSATION_ID, conversationId))
    .user(userText)
    .call()
	.content();

    建议在构建时通过构建器的 `defaultAdvisors()` 方法注册顾问。

    顾问也参与可观测性栈，因此您可以查看与其执行相关的指标和追踪信息。

    • 了解问答顾问

    • 了解聊天记忆顾问

    核心组件

    API 包含用于非流式场景的CallAdvisor和CallAdvisorChain，以及用于流式场景的StreamAdvisor和StreamAdvisorChain。此外，还包括表示未密封 Prompt 请求的ChatClientRequest和表示 Chat Completion 响应的ChatClientResponse。两者均持有advise-context，以便在顾问链之间共享状态。

    `adviseCall()` 和 `adviseStream()` 是关键的建议方法，通常执行诸如检查未密封的 Prompt 数据、定制和增强 Prompt 数据、调用建议链中的下一个实体、可选地阻塞请求、检查聊天完成响应以及抛出异常以指示处理错误等操作。

    此外，`getOrder()` 方法用于确定链中顾问的顺序，而 `getName()` 则提供唯一的顾问名称。

    由 Spring AI 框架创建的顾问链（Advisor Chain）允许按 `getOrder()` 值对多个顾问进行排序并依次调用。数值较低的顾问优先执行。最后自动添加的顾问负责将请求发送至 LLM。

    下图展示了顾问链与聊天模型之间的交互流程：

    1. Spring AI 框架会从用户的 `Prompt` 创建一个 `ChatClientRequest`，并附带一个空的顾问 `context` 对象。

    2. 链中的每个顾问都会处理该请求，并可能对其进行修改。或者，它可以选择通过不发起调用以触发下一个实体来阻止该请求。在后一种情况下，由该顾问负责填写响应内容。

    3. 最终由框架提供的顾问将请求发送至Chat Model。

    4. 随后，聊天模型的响应将通过顾问链回传并转换为ChatClientResponse。该响应后续将包含共享的顾问context实例。

    5. 每位顾问均可处理或修改该响应。

    6. 最终的ChatClientResponse通过提取ChatCompletion返回给客户端。

    顾问订单

    链中顾问的执行顺序由 getOrder() 方法决定。需要理解的关键点如下：

    • 执行顺序较低的建议将首先被执行。

    • 顾问链以栈的形式运作：

      • 链中的第一个顾问是首先处理请求的。

      • 它也是最后处理响应的组件。

    • 控制执行顺序：

      • 将顺序设置为接近 `Ordered.HIGHEST_PRECEDENCE`，以确保在顾问链中首先执行该顾问（请求处理时最先执行，响应处理时最后执行）。

      • 将顺序设置为接近 `Ordered.LOWEST_PRECEDENCE`，以确保顾问在链中最后执行（请求处理时最后执行，响应处理时最先执行）。

    • 数值越高，优先级越低。

    • 如果多个顾问的订单价值相同，则其执行顺序无法保证。

    顺序与执行序列之间看似矛盾的现象，是由于顾问链具有栈的特性所致：

    • 优先级最高（数值最小）的顾问被添加到栈顶。

    • 它将在栈展开时首先处理该请求。

    • 它将是栈回退时最后处理响应的部分。

    作为提醒，以下是 Spring `Ordered` 接口的语义：

    public interface Ordered {

    /**
     * Constant for the highest precedence value.
     * @see java.lang.Integer#MIN_VALUE
     */
    int HIGHEST_PRECEDENCE = Integer.MIN_VALUE;

    /**
     * Constant for the lowest precedence value.
     * @see java.lang.Integer#MAX_VALUE
     */
    int LOWEST_PRECEDENCE = Integer.MAX_VALUE;

    /**
     * Get the order value of this object.
     * <p>Higher values are interpreted as lower priority. As a consequence,
     * the object with the lowest value has the highest priority (somewhat
     * analogous to Servlet {@code load-on-startup} values).
     * <p>Same order values will result in arbitrary sort positions for the
     * affected objects.
     * @return the order value
     * @see #HIGHEST_PRECEDENCE
     * @see #LOWEST_PRECEDENCE
     */
    int getOrder();
}

    适用于需要在输入和输出端均处于链首的使用场景：

    1. 为双方分别聘请顾问。

    2. 为它们配置不同的订单值。

    3. 使用顾问上下文在它们之间共享状态。

    API 概述

    主要顾问接口位于包 org.springframework.ai.chat.client.advisor.api 中。以下是创建自定义顾问时遇到的关键接口：

    public interface Advisor extends Ordered {

	String getName();

}

    同步和反应式 Advisor 的两个子接口是

    public interface CallAdvisor extends Advisor {

	ChatClientResponse adviseCall(
		ChatClientRequest chatClientRequest, CallAdvisorChain callAdvisorChain);

}

    and

    public interface StreamAdvisor extends Advisor {

	Flux<ChatClientResponse> adviseStream(
		ChatClientRequest chatClientRequest, StreamAdvisorChain streamAdvisorChain);

}

    要继续 Advice 链，请在您的 Advice 实现中使用CallAdvisorChain和StreamAdvisorChain：

    接口是

    public interface CallAdvisorChain extends AdvisorChain {

	/**
	 * Invokes the next {@link CallAdvisor} in the {@link CallAdvisorChain} with the given
	 * request.
	 */
	ChatClientResponse nextCall(ChatClientRequest chatClientRequest);

	/**
	 * Returns the list of all the {@link CallAdvisor} instances included in this chain at
	 * the time of its creation.
	 */
	List<CallAdvisor> getCallAdvisors();

}

    and

    public interface StreamAdvisorChain extends AdvisorChain {

	/**
	 * Invokes the next {@link StreamAdvisor} in the {@link StreamAdvisorChain} with the
	 * given request.
	 */
	Flux<ChatClientResponse> nextStream(ChatClientRequest chatClientRequest);

	/**
	 * Returns the list of all the {@link StreamAdvisor} instances included in this chain
	 * at the time of its creation.
	 */
	List<StreamAdvisor> getStreamAdvisors();

}

    实施顾问

    要创建顾问，请实现CallAdvisor或StreamAdvisor（或两者都实现）。关键方法是针对非流式顾问实现nextCall()，或针对流式顾问实现nextStream()。

    Examples

    我们将提供几个动手示例，以说明如何实现顾问来观察和增强用例。

    日志顾问

    我们可以实现一个简单的日志记录顾问，在调用链中下一个顾问之前记录 ChatClientRequest，并在之后记录 ChatClientResponse。 请注意，该顾问仅观察请求和响应，不会对其进行修改。 此实现同时支持非流式和流式场景。

    public class SimpleLoggerAdvisor implements CallAdvisor, StreamAdvisor {

	private static final Logger logger = LoggerFactory.getLogger(SimpleLoggerAdvisor.class);

	@Override
	public String getName() { (1)
		return this.getClass().getSimpleName();
	}

	@Override
	public int getOrder() { (2)
		return 0;
	}


	@Override
	public ChatClientResponse adviseCall(ChatClientRequest chatClientRequest, CallAdvisorChain callAdvisorChain) {
		logRequest(chatClientRequest);

		ChatClientResponse chatClientResponse = callAdvisorChain.nextCall(chatClientRequest);

		logResponse(chatClientResponse);

		return chatClientResponse;
	}

	@Override
	public Flux<ChatClientResponse> adviseStream(ChatClientRequest chatClientRequest,
			StreamAdvisorChain streamAdvisorChain) {
		logRequest(chatClientRequest);

		Flux<ChatClientResponse> chatClientResponses = streamAdvisorChain.nextStream(chatClientRequest);

		return new ChatClientMessageAggregator().aggregateChatClientResponse(chatClientResponses, this::logResponse); (3)
	}

	private void logRequest(ChatClientRequest request) {
		logger.debug("request: {}", request);
	}

	private void logResponse(ChatClientResponse chatClientResponse) {
		logger.debug("response: {}", chatClientResponse);
	}

}
    1 为顾问提供唯一名称。
    2 您可以通过设置顺序值来控制执行顺序。数值越低，执行越早。
    3 MessageAggregator 是一个工具类，用于将 Flux 响应聚合为单个 ChatClientResponse。这对于日志记录或其他需要观察整个响应而非流中单个项的处理非常有用。请注意，您无法在 MessageAggregator 中修改响应，因为这是一个只读操作。

    Re-Reading (Re2) Advisor

    《重读提升大语言模型的推理能力》一文介绍了一种名为“重读”（Re2）的技术，该技术能够增强大语言模型的推理能力。 Re2 技术需要对输入提示进行如下增强：

    {Input_Query}
Read the question again: {Input_Query}

    可以通过以下方式实现一个应用 Re2 技术对用户输入查询进行处理的顾问：

    public class ReReadingAdvisor implements BaseAdvisor {

	private static final String DEFAULT_RE2_ADVISE_TEMPLATE = """
			{re2_input_query}
			Read the question again: {re2_input_query}
			""";

	private final String re2AdviseTemplate;

	private int order = 0;

	public ReReadingAdvisor() {
		this(DEFAULT_RE2_ADVISE_TEMPLATE);
	}

	public ReReadingAdvisor(String re2AdviseTemplate) {
		this.re2AdviseTemplate = re2AdviseTemplate;
	}

	@Override
	public ChatClientRequest before(ChatClientRequest chatClientRequest, AdvisorChain advisorChain) { (1)
		String augmentedUserText = PromptTemplate.builder()
			.template(this.re2AdviseTemplate)
			.variables(Map.of("re2_input_query", chatClientRequest.prompt().getUserMessage().getText()))
			.build()
			.render();

		return chatClientRequest.mutate()
			.prompt(chatClientRequest.prompt().augmentUserMessage(augmentedUserText))
			.build();
	}

	@Override
	public ChatClientResponse after(ChatClientResponse chatClientResponse, AdvisorChain advisorChain) {
		return chatClientResponse;
	}

	@Override
	public int getOrder() { (2)
		return this.order;
	}

	public ReReadingAdvisor withOrder(int order) {
		this.order = order;
		return this;
	}

}
    1 before 方法通过应用重读技术来增强用户的输入查询。
    2 您可以通过设置顺序值来控制执行顺序。数值越小，执行越早。

    Spring AI 内置顾问

    Spring AI 框架提供了几种内置顾问，以增强您的 AI 交互。以下是可用顾问的概述：

    对话记忆顾问

    这些顾问在聊天记忆存储中管理对话历史：

    • MessageChatMemoryAdvisor

      检索记忆并将其作为消息集合添加到提示中。这种方法保持了对话历史的结构。请注意，并非所有 AI 模型都支持此方法。

    • VectorStoreChatMemoryAdvisor

      从向量存储中检索记忆并将其添加到提示的系统文本中。此顾问有助于高效地从大型数据集中搜索和检索相关信息。

    问答顾问

    • QuestionAnswerAdvisor

      该顾问使用向量存储提供问答功能，并实现了朴素 RAG（检索增强生成）模式。

    • RetrievalAugmentationAdvisor

      实现基于org.springframework.ai.rag包中定义的构建块并遵循模块化 RAG 架构的通用检索增强生成（RAG）流程的顾问。

    推理顾问

    • ReReadingAdvisor

      提出了一种名为 RE2 的大语言模型推理重读策略，以增强输入阶段的理解能力。 基于文章：重读可提升大语言模型的推理能力。

    工具调用顾问

    • ToolCallingAdvisor

      作为顾问链的一部分处理工具调用循环。该顾问始终由 `ChatClient` 自动注册（除非显式禁用），因此即使未配置静态工具，也支持通过另一个顾问在运行时注入的工具。它会执行模型请求的工具调用并将结果返回，持续迭代直到不再需要更多工具调用。实现了 `ToolAdvisor` 接口，这是一个标记接口，用于防止第二个 `ToolCallingAdvisor` 被自动注册。

      有关完整文档，请参阅递归顾问 - ToolCallingAdvisor和ChatClient - 工具调用。

    内容安全顾问

    • SafeGuardAdvisor

      一款旨在防止模型生成有害或不适当内容的简单顾问。

    流式传输与非流式传输

    • 非流式顾问处理完整的请求和响应。

    • 流式顾问以连续流的形式处理请求和响应，采用反应式编程概念（例如使用 Flux 处理响应）。

    @Override
public Flux<ChatClientResponse> adviseStream(ChatClientRequest chatClientRequest, StreamAdvisorChain chain) {

    return  Mono.just(chatClientRequest)
            .publishOn(Schedulers.boundedElastic())
            .map(request -> {
                // This can be executed by blocking and non-blocking Threads.
                // Advisor before next section
            })
            .flatMapMany(request -> chain.nextStream(request))
            .map(response -> {
                // Advisor after next section
            });
}

    最佳实践

    1. 使顾问专注于特定任务，以实现更好的模块化。

    2. 必要时使用 `adviseContext` 在顾问之间共享状态。

    3. 实现顾问的流式和非流式版本，以获得最大的灵活性。

    4. 请仔细考虑您链中顾问的顺序，以确保数据流正确无误。

    破坏性 API 变更

    顾问接口

    • 在 1.0 版 M2 中，存在独立的RequestAdvisor和ResponseAdvisor接口。

      • 在调用 `ChatModel.call` 和 `ChatModel.stream` 方法之前，已调用了 `RequestAdvisor`。

      • 在调用这些方法之后，会调用 ResponseAdvisor。

    • 在 1.0 M3 版本中，这些接口已被替换为：

      • CallAroundAdvisor

      • StreamAroundAdvisor

    • StreamResponseMode 已从 ResponseAdvisor 中移除。

    • 在 1.0.0 版本中，这些接口已被替换：

      • CallAroundAdvisor → CallAdvisor, StreamAroundAdvisor → StreamAdvisor, CallAroundAdvisorChain → CallAdvisorChain and StreamAroundAdvisorChain → StreamAdvisorChain.

      • AdvisedRequest → ChatClientRequest and AdivsedResponse → ChatClientResponse.

    上下文映射处理

    • 在 1.0 M2：

      • 上下文映射是一个独立的方法参数。

      • 该地图是可变的，并在链中传递。

    • 在 1.0 M3：

      • 上下文映射现已成为AdvisedRequest和AdvisedResponse记录的一部分。

      • 该地图是不可变的。

      • 要更新上下文，请使用 `updateContext` 方法，该方法会创建一个包含更新后内容的新不可变映射。
