    聊天记忆

    大型语言模型（LLMs）是无状态的，这意味着它们不会保留之前交互的信息。当需要在多次交互之间保持上下文或状态时，这可能成为一个限制。为了解决这个问题，Spring AI 提供了聊天记忆功能，允许您在与大型语言模型的多次交互中存储和检索信息。

    `ChatMemory` 抽象允许您实现各种类型的内存以支持不同的使用场景。消息的底层存储由 `ChatMemoryRepository` 处理，其唯一职责是存储和检索消息。具体保留哪些消息以及何时移除它们，则由 `ChatMemory` 的实现来决定。策略示例包括保留最后 N 条消息、保留特定时间段内的消息，或保留直到达到某个令牌限制的消息。

    在选择记忆类型之前，必须理解聊天记忆与聊天历史之间的区别。

    • 对话记忆。大型语言模型在对话过程中保留并利用的信息，以维持上下文感知能力。

    • 聊天记录。包含用户与模型之间交换的所有消息的完整对话历史。

    `ChatMemory` 抽象类旨在管理对话记忆，允许您存储和检索与当前对话上下文相关的消息。然而，它并非存储对话历史的最佳选择。如果您需要维护所有交换消息的完整记录，应考虑采用其他方法，例如依赖 Spring Data 来高效地存储和检索完整的对话历史。

    快速开始

    Spring AI 会自动配置一个ChatMemory Bean，您可以直接在应用程序中使用它。默认情况下，它会使用内存存储库来保存消息（InMemoryChatMemoryRepository），并使用MessageWindowChatMemory实现来管理对话历史。如果已经配置了不同的存储库（例如 Cassandra、JDBC 或 Neo4j），Spring AI 将使用该存储库。

    @Autowired
ChatMemory chatMemory;

    以下章节将进一步介绍 Spring AI 中可用的不同类型内存和存储库。

    内存类型

    `ChatMemory` 抽象允许您实现各种类型的内存以适应不同的使用场景。内存类型的选择会显著影响应用程序的性能和行为。本节介绍 Spring AI 提供的内置内存类型及其特性。

    消息窗口聊天记忆

    `MessageWindowChatMemory` 维护一个消息滑动窗口，其大小不超过指定的最大值。当消息数量超过最大值时，会移除较旧的消息，同时始终保留 `SystemMessage` 实例。默认窗口大小为 20 条消息。

    MessageWindowChatMemory memory = MessageWindowChatMemory.builder()
    .maxMessages(10)
    .build();

    这是 Spring AI 用于自动配置 `ChatMemory` Bean 的默认消息类型。

    轮次边界驱逐

    当需要驱逐时，MessageWindowChatMemory 总是移除整个回合，而不是在回合中间截断。一个回合始于一个UserMessage，并包含直到下一个UserMessage之前的所有后续助手回复、工具调用和工具响应。如果原始驱逐点落在非用户消息上（例如，处于工具调用交换过程中的助手回复），则会将截断点向前推进到下一个UserMessage，以确保保留的窗口始终从完整的回合开始。

    这意味着maxMessages是存储消息数量的上限——当需要取整以找到下一个回合边界时，实际数量可能会略低。

    如果 maxMessages 小于单个完整轮次（例如，超过窗口大小的多步工具调用交互），所有非系统消息都可能会被驱逐，直到添加一个新的 UserMessage。请根据您的需求，将 maxMessages 设置得足够大，以确保至少能容纳一个代表性的轮次。

    内存存储

    Spring AI 提供了用于存储聊天记忆的 `ChatMemoryRepository` 抽象。本节介绍了 Spring AI 提供的内置仓库及其使用方法，但如有需要，您也可以自行实现自己的仓库。

    Azure Cosmos DB 聊天记忆存储库支持作为由 Azure Cosmos DB 团队维护的外部模块提供。有关更多信息，请参阅 azurecosmosdb.github.io/spring-ai/docs/index.html。

    内存存储库

    InMemoryChatMemoryRepository 使用 ConcurrentHashMap 在内存中存储消息。

    默认情况下，如果未配置其他存储库，Spring AI 会自动配置一个类型为 InMemoryChatMemoryRepository 的 ChatMemoryRepository Bean，您可以直接在应用程序中使用它。

    @Autowired
ChatMemoryRepository chatMemoryRepository;

    如果您更倾向于手动创建InMemoryChatMemoryRepository，可以按以下方式操作：

    ChatMemoryRepository repository = new InMemoryChatMemoryRepository();

    JdbcChatMemoryRepository

    JdbcChatMemoryRepository 是一个内置实现，使用 JDBC 将消息存储到关系型数据库中。它开箱即支持多种数据库，适用于需要持久化存储聊天记忆的应用程序。

    消息按升序（从旧到新）检索，这是 LLM 对话历史预期的格式。顺序由记录每条消息在其对话中位置的 `sequence_id` 列维护。每条消息还存储一个创建时间戳 `timestamp`，该时间戳在消息元数据下通过 `JdbcChatMemoryRepository.CONVERSATION_TS` 键暴露为 `java.time.Instant`，以便应用程序可以显示消息的创建时间。

    JdbcChatMemoryRepository 不支持工具调用消息。 包含工具调用的 AssistantMessage 实例和 ToolResponseMessage 实例在保存时会被静默过滤，不会出现在检索到的对话历史中。 如果您的应用程序使用工具调用功能，请考虑 Spring AI Session 项目及其 JDBC 会话存储，它们能够正确持久化所有消息类型。

    首先，将以下依赖项添加到您的项目中：

    • Maven

    • Gradle

    <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-chat-memory-repository-jdbc</artifactId>
</dependency>
    dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-model-chat-memory-repository-jdbc'
}

    Spring AI 为JdbcChatMemoryRepository提供了自动配置功能，您可以直接在应用程序中使用它。

    @Autowired
JdbcChatMemoryRepository chatMemoryRepository;

ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .chatMemoryRepository(chatMemoryRepository)
    .maxMessages(10)
    .build();

    如果您更愿意手动创建JdbcChatMemoryRepository，可以通过提供一个JdbcTemplate实例和一个JdbcChatMemoryRepositoryDialect来实现：

    ChatMemoryRepository chatMemoryRepository = JdbcChatMemoryRepository.builder()
    .jdbcTemplate(jdbcTemplate)
    .dialect(new PostgresChatMemoryRepositoryDialect())
    .build();

ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .chatMemoryRepository(chatMemoryRepository)
    .maxMessages(10)
    .build();

    阅读消息时间戳

    每条存储的消息都记录了其创建时间。该时间戳可在消息元数据中的 `JdbcChatMemoryRepository.CONVERSATION_TS` 键下以 `java.time.Instant` 格式获取，这对于在用户界面中显示消息时间非常有用：

    List<Message> messages = chatMemory.get(conversationId);
for (Message message : messages) {
    Instant createdAt = (Instant) message.getMetadata().get(JdbcChatMemoryRepository.CONVERSATION_TS);
}

    当对话被再次保存时，时间戳会被保留，因此消息在其整个对话生命周期内保持其原始创建时间。

    支持的数据库和方言抽象

    Spring AI 通过方言抽象支持多种关系型数据库。以下数据库开箱即用：

    • PostgreSQL

    • MySQL / MariaDB

    • SQL Server

    • HSQLDB

    • Oracle 数据库

    使用 `JdbcChatMemoryRepositoryDialect.from(DataSource)` 时，正确的方言可以从 JDBC URL 中自动检测。您可以通过实现 `JdbcChatMemoryRepositoryDialect` 接口来扩展对其他数据库的支持。

    模式初始化

    自动配置将在启动时自动创建 `SPRING_AI_CHAT_MEMORY` 表，并使用针对您数据库的特定供应商 SQL 脚本。默认情况下，模式初始化仅针对嵌入式数据库（如 H2、HSQL、Derby 等）运行。

    自 2.0.0 版本起，架构新增了一个 sequence_id 列用于确定消息顺序，同时保留了现有的 timestamp 列（现已通过消息元数据暴露）。升级现有应用程序需要添加此新列；迁移步骤请参阅升级说明。

    您可以使用 `spring.ai.chat.memory.repository.jdbc.initialize-schema` 属性来控制模式初始化：

    spring.ai.chat.memory.repository.jdbc.initialize-schema=embedded # Only for embedded DBs (default)
spring.ai.chat.memory.repository.jdbc.initialize-schema=always   # Always initialize
spring.ai.chat.memory.repository.jdbc.initialize-schema=never    # Never initialize (useful with Flyway/Liquibase)

    要覆盖模式脚本位置，请使用：

    spring.ai.chat.memory.repository.jdbc.schema=classpath:/custom/path/schema-mysql.sql

    扩展方言

    要支持新数据库，请实现 JdbcChatMemoryRepositoryDialect 接口并提供用于选择、插入和删除消息的 SQL 语句。然后，您可以将自定义方言传递给仓库构建器。

    ChatMemoryRepository chatMemoryRepository = JdbcChatMemoryRepository.builder()
    .jdbcTemplate(jdbcTemplate)
    .dialect(new MyCustomDbDialect())
    .build();

    CassandraChatMemoryRepository

    CassandraChatMemoryRepository 使用 Apache Cassandra 存储消息。它适用于需要持久化存储聊天记忆的应用程序，特别是在对可用性、耐久性、可扩展性以及利用时间到活（TTL）功能有需求时。

    `CassandraChatMemoryRepository` 采用时间序列架构，用于保存所有历史聊天窗口的记录，这对于治理和审计至关重要。建议将生存时间（time-to-live）设置为某个值，例如三年。

    消息按时间戳升序（从旧到新）检索，这是大型语言模型对话历史所需的预期格式。

    要使用 CassandraChatMemoryRepository，首先请在您的项目中添加该依赖：

    • Maven

    • Gradle

    <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-chat-memory-repository-cassandra</artifactId>
</dependency>
    dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-model-chat-memory-repository-cassandra'
}

    Spring AI 为 `CassandraChatMemoryRepository` 提供了自动配置功能，您可以直接在应用程序中使用它。

    @Autowired
CassandraChatMemoryRepository chatMemoryRepository;

ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .chatMemoryRepository(chatMemoryRepository)
    .maxMessages(10)
    .build();

    如果您更倾向于手动创建 CassandraChatMemoryRepository，可以通过提供一个 CassandraChatMemoryRepositoryConfig 实例来实现：

    ChatMemoryRepository chatMemoryRepository = CassandraChatMemoryRepository
    .create(CassandraChatMemoryRepositoryConfig.builder().withCqlSession(cqlSession));

ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .chatMemoryRepository(chatMemoryRepository)
    .maxMessages(10)
    .build();

    Neo4j 聊天记忆存储库

    Neo4jChatMemoryRepository 是一个内置实现，它利用 Neo4j 将聊天消息存储为属性图数据库中的节点和关系。该实现适用于希望利用 Neo4j 的图能力进行聊天记忆持久化的应用程序。

    消息按消息索引升序（从旧到新）获取，这是大语言模型对话历史所需的预期格式。

    首先，将以下依赖项添加到您的项目中：

    • Maven

    • Gradle

    <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-chat-memory-repository-neo4j</artifactId>
</dependency>
    dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-model-chat-memory-repository-neo4j'
}

    Spring AI 为 `Neo4jChatMemoryRepository`》提供了自动配置功能，您可以直接在应用程序中使用它。

    @Autowired
Neo4jChatMemoryRepository chatMemoryRepository;

ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .chatMemoryRepository(chatMemoryRepository)
    .maxMessages(10)
    .build();

    如果您更倾向于手动创建Neo4jChatMemoryRepository，可以通过提供一个 Neo4j Driver 实例来实现：

    ChatMemoryRepository chatMemoryRepository = Neo4jChatMemoryRepository.builder()
    .driver(driver)
    .build();

ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .chatMemoryRepository(chatMemoryRepository)
    .maxMessages(10)
    .build();

    MongoChatMemoryRepository

    MongoChatMemoryRepository 是一个内置实现，使用 MongoDB 存储消息。它适用于需要灵活文档型数据库来持久化聊天记忆的应用程序。

    消息按时间戳升序（从旧到新）检索，这是大型语言模型对话历史所需的预期格式。此排序在所有聊天记忆存储库实现中均保持一致。

    MongoChatMemoryRepository 不支持工具调用消息。 包含工具调用的 AssistantMessage 实例和 ToolResponseMessage 实例在保存时会被静默过滤，不会出现在检索到的对话历史中。 如果您的应用程序使用工具调用功能，请考虑 Spring AI Session 项目和 JDBC 会话存储，它们能够正确持久化所有消息类型。

    首先，将以下依赖项添加到您的项目中：

    • Maven

    • Gradle

    <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-chat-memory-repository-mongodb</artifactId>
</dependency>
    dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-model-chat-memory-repository-mongodb'
}

    Spring AI 为 `MongoChatMemoryRepository` 提供了自动配置，您可以直接在应用程序中使用它。

MongoChatMemoryRepository chatMemoryRepository;

ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .chatMemoryRepository(chatMemoryRepository)

    .build();

    .mongoTemplate(mongoTemplate)
    .build();

ChatMemory chatMemory = MessageWindowChatMemory.builder()
    .chatMemoryRepository(chatMemoryRepository)
    .maxMessages(10)
    .build();

    RedisChatMemoryRepository

    RedisChatMemoryRepository 是一个内置实现，利用 Redis Stack（包含 Redis Query Engine 和 RedisJSON）来存储聊天消息。它适用于需要高性能、低延迟聊天记忆持久化的应用程序，并支持可选的 TTL（生存时间）功能和高级查询能力。

    该仓库以 JSON 文档形式存储消息，并创建搜索索引以实现高效查询。此外，它通过 `AdvancedRedisChatMemoryRepository` 接口提供扩展的查询功能，支持按内容、类型、时间范围和元数据搜索消息。

    消息按时间戳升序（从旧到新）检索，这是大型语言模型对话历史所需的预期格式。

    首先，将以下依赖项添加到您的项目中：

    高级查询

    RedisChatMemoryRepository 还实现了 AdvancedRedisChatMemoryRepository，后者提供了扩展的查询功能：

    // Cast to access advanced features
AdvancedRedisChatMemoryRepository advancedRepo = (AdvancedRedisChatMemoryRepository) chatMemoryRepository;

// Find messages by type across all conversations
List<MessageWithConversation> userMessages = advancedRepo.findByType(MessageType.USER, 100);

// Find messages containing specific content
List<MessageWithConversation> results = advancedRepo.findByContent("Spring AI", 50);

// Find messages within a time range
List<MessageWithConversation> recentMessages = advancedRepo.findByTimeRange(
    conversationId,
    Instant.now().minus(Duration.ofHours(1)),
    Instant.now(),
    100
);

// Find messages by metadata
List<MessageWithConversation> priorityMessages = advancedRepo.findByMetadata("priority", "high", 50);

// Execute custom Redis queries
List<MessageWithConversation> customResults = advancedRepo.executeQuery("@type:USER @content:Redis", 100);

    spring.ai.chat.memory.redis.metadata-fields[0].name=priority
spring.ai.chat.memory.redis.metadata-fields[0].type=tag
spring.ai.chat.memory.redis.metadata-fields[1].name=score
spring.ai.chat.memory.redis.metadata-fields[1].type=numeric
spring.ai.chat.memory.redis.metadata-fields[2].name=category

    支持的字段类型包括：tag（用于精确匹配过滤）、text（用于全文搜索）和numeric（用于范围查询）。

    模式初始化

    自动配置会在启动时自动创建 Redis 搜索索引（如果尚不存在）。 您可以通过设置 `spring.ai.chat.memory.redis.initialize-schema=false` 来禁用此行为。

    • Redis Stack 7.0 或更高版本（包含 Redis 查询引擎和 RedisJSON 模块）

    • Jedis 客户端库（作为依赖项包含）

    聊天客户端中的记忆

    在使用 ChatClient API 时，您可以提供一个 ChatMemory 实现来在多次交互之间维护对话上下文。

    Spring AI 提供了一些内置的 Advisor，您可以根据需求使用它们来配置 ChatClient 的记忆行为。

    目前，在执行工具调用时与大语言模型交换的中间消息不会存储在内存中。这是当前实现的局限性，将在未来的版本中解决。如果您需要存储这些消息，请参考用户控制的工具执行中的说明。

    • `MessageChatMemoryAdvisor`。该顾问使用提供的 `ChatMemory` 实现来管理对话记忆。在每次交互中，它会从记忆中检索对话历史，并将其作为消息集合包含在提示中。

    • VectorStoreChatMemoryAdvisor。该顾问使用提供的 VectorStore 实现来管理对话记忆。在每次交互中，它从向量存储中检索对话历史，并将其作为纯文本附加到系统消息中。

    例如，如果您想使用 `MessageWindowChatMemory` 与 `MessageChatMemoryAdvisor` 配合，可以按以下方式配置：

    ChatMemory chatMemory = MessageWindowChatMemory.builder().build();

ChatClient chatClient = ChatClient.builder(chatModel)
    .defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
    .build();

    调用ChatClient时，内存将由MessageChatMemoryAdvisor自动管理。对话历史将根据指定的会话ID从内存中检索。

    对于所有记忆顾问，ChatMemory.CONVERSATION_ID 参数是必需的。如果调用时省略此参数，将在运行时抛出 IllegalArgumentException 异常。不存在默认的会话 ID。 
    String conversationId = "007";

chatClient.prompt()
    .user("Do I have license to code?")
    .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
    .call()
    .content();

    VectorStoreChatMemoryAdvisor

    自定义模板

    `VectorStoreChatMemoryAdvisor` 使用默认模板将检索到的对话记忆附加到系统消息中。您可以通过 `.promptTemplate()` 构建器方法提供自己的 `PromptTemplate` 对象来自定义此行为。

    此处提供的 PromptTemplate 自定义了顾问如何将检索到的记忆与系统消息合并。这与在 ChatClient 本身配置 TemplateRenderer（使用 .templateRenderer()）不同，后者影响的是在顾问运行之前对初始用户/系统提示内容的渲染。有关客户端级模板渲染的更多详细信息，请参阅ChatClient 提示模板。

    自定义的 PromptTemplate 可以使用任何 TemplateRenderer 实现（默认情况下，它基于 StringTemplate 引擎使用 StPromptTemplate）。关键要求是模板必须包含以下两个占位符：

    • 一个用于接收原始系统消息的 `instructions` 占位符。

    • 一个 `long_term_memory` 占位符，用于接收检索到的对话记忆。

    聊天模型中的记忆

    如果您直接使用 `ChatModel` 而非 `ChatClient，则可以显式管理内存：

    // Create a memory instance
ChatMemory chatMemory = MessageWindowChatMemory.builder().build();
String conversationId = "007";

// First interaction
UserMessage userMessage1 = new UserMessage("My name is James Bond");
chatMemory.add(conversationId, userMessage1);
ChatResponse response1 = chatModel.call(new Prompt(chatMemory.get(conversationId)));
chatMemory.add(conversationId, response1.getResult().getOutput());

// Second interaction
UserMessage userMessage2 = new UserMessage("What is my name?");
chatMemory.add(conversationId, userMessage2);
ChatResponse response2 = chatModel.call(new Prompt(chatMemory.get(conversationId)));
chatMemory.add(conversationId, response2.getResult().getOutput());

// The response will contain "James Bond"
