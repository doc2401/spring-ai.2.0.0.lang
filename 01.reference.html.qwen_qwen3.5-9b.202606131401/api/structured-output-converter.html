    结构化输出转换器

    大型语言模型生成结构化输出的能力对于依赖可靠解析输出值的下游应用至关重要。开发者希望快速将人工智能模型的结果转换为其他应用程序函数和方法可使用的数据类型，例如 JSON、XML 或 Java 类。

    Spring AI 的结构化输出转换器有助于将大语言模型（LLM）的输出转换为结构化格式。 如下图所示，该方法围绕 LLM 文本补全端点运行：

    使用通用补全 API 从大型语言模型（LLM）生成结构化输出需要仔细处理输入和输出。结构化输出转换器在 LLM 调用前后起着至关重要的作用，确保实现所需的输出结构。

    在大语言模型调用之前，转换器会将格式指令附加到提示中，为模型生成所需的输出结构提供明确指导。这些指令充当蓝图，塑造模型的响应以符合指定的格式。

    随着越来越多的 AI 模型原生支持结构化输出，您可以利用 Native Structured Output 功能配合 AdvisorParams.ENABLE_NATIVE_STRUCTURED_OUTPUT 来发挥这一能力。这种方法直接使用生成的 JSON Schema 与模型的原生结构化输出 API，无需预先编写提示词格式指令，从而提供更可靠的结果。

    在大语言模型调用之后，转换器将模型的输出文本转换为结构化类型的实例。该转换过程涉及解析原始文本输出，并将其映射到相应的结构化数据表示形式，例如 JSON、XML 或特定领域的数据结构。

    StructuredOutputConverter 会尽力将模型输出转换为结构化输出。 AI 模型并不保证能返回按请求的结构化输出。 模型可能无法理解提示，或无法生成按请求的结构化输出。 建议实现验证机制，以确保模型输出符合预期。
    StructuredOutputConverter 不用于 LLM 工具调用，因为该功能默认本身就提供结构化输出。

    结构化输出 API

    `StructuredOutputConverter` 接口允许您获取结构化输出，例如将基于文本的 AI 模型输出映射为 Java 类或值数组。 接口定义如下：

    public interface StructuredOutputConverter<T> extends Converter<String, T>, FormatProvider {

}

    它结合了 Spring 的Converter<String, T>接口和FormatProvider接口。

    public interface FormatProvider {
	String getFormat();
}

    下图展示了使用结构化输出 API 时的数据流。

    FormatProvider 为 AI 模型提供特定的格式化指南，使其能够生成可通过 Converter 转换为指定目标类型 T 的文本输出。以下是此类格式化指令的一个示例：

      Your response should be in JSON format.
  The data structure for the JSON should match this Java class: java.util.HashMap
  Do not include any explanations, only provide a RFC8259 compliant JSON response following this format without deviation.

    格式说明通常使用类似PromptTemplate的方式附加在用户输入的末尾，如下所示：

        StructuredOutputConverter outputConverter = ...
    String userInputTemplate = """
        ... user text input ....
        {format}
        """; // user input with a "format" placeholder.
    Prompt prompt = new Prompt(
            PromptTemplate.builder()
						.template(this.userInputTemplate)
						.variables(Map.of(..., "format", this.outputConverter.getFormat())) // replace the "format" placeholder with the converter's format.
						.build().createMessage()
    );

    Converter 负责将模型输出的文本转换为指定类型 T 的实例。

    可用转换器

    目前，Spring AI 提供了以下实现：AbstractConversionServiceOutputConverter、AbstractMessageOutputConverter、BeanOutputConverter、MapOutputConverter 和 ListOutputConverter：

    • AbstractConversionServiceOutputConverter<T> - 提供预配置的 GenericConversionService，用于将 LLM 输出转换为所需格式。未提供默认的 FormatProvider 实现。

    • AbstractMessageOutputConverter<T> - 提供用于将 LLM 输出转换为所需格式的预配置MessageConverter。未提供任何默认的FormatProvider实现。

    • BeanOutputConverter<T> - 配置为指定的 Java 类（例如 Bean）或一个 ParameterizedTypeReference，该转换器采用 FormatProvider 实现，指导 AI 模型生成符合由指定 Java 类导出的 DRAFT_2020_12 JSON Schema 的 JSON 响应。随后，它利用 JsonMapper 将 JSON 输出反序列化为目标类的 Java 对象实例。

    • MapOutputConverter - 在 AbstractMessageOutputConverter 的功能基础上，扩展了带有 FormatProvider 实现的版本，该实现引导 AI 模型生成符合 RFC8259 标准的 JSON 响应。此外，它还集成了转换器实现，利用提供的 MessageConverter 将 JSON 负载转换为 java.util.Map<String, Object> 实例。

    • ListOutputConverter 扩展了 AbstractConversionServiceOutputConverter，并包含一个专为逗号分隔列表输出定制的 FormatProvider 实现。该转换器利用提供的 ConversionService 将模型文本输出转换为 java.util.List。

    使用转换器

    以下章节提供了如何使用可用转换器生成结构化输出的指南。

    Bean 输出转换器

    以下示例展示了如何使用 `BeanOutputConverter` 为演员生成作品年表。

    代表演员电影履历的目标记录：

    record ActorsFilms(String actor, List<String> movies) {
}

    以下是如何使用高级流式ChatClientAPI 应用 BeanOutputConverter 的方法：

    ActorsFilms actorsFilms = ChatClient.create(chatModel).prompt()
        .user(u -> u.text("Generate the filmography of 5 movies for {actor}.")
                    .param("actor", "Tom Hanks"))
        .call()
        .entity(ActorsFilms.class);

    或使用低级别的ChatModelAPI 直接调用：

    BeanOutputConverter<ActorsFilms> beanOutputConverter =
    new BeanOutputConverter<>(ActorsFilms.class);

String format = this.beanOutputConverter.getFormat();

String actor = "Tom Hanks";

String template = """
        Generate the filmography of 5 movies for {actor}.
        {format}
        """;

Generation generation = chatModel.call(
    PromptTemplate.builder().template(this.template).variables(Map.of("actor", this.actor, "format", this.format)).build().create()).getResult();

ActorsFilms actorsFilms = this.beanOutputConverter.convert(this.generation.getOutput().getText());

    生成模式中的属性排序

    BeanOutputConverter 支持通过 @JsonPropertyOrder 注解在生成的 JSON Schema 中自定义属性顺序。 该注解允许您指定属性在 Schema 中出现的精确顺序，而无需考虑其在类或记录中的声明顺序。

    例如，为确保 `ActorsFilms` 记录中属性的特定顺序：

    @JsonPropertyOrder({"actor", "movies"})
record ActorsFilms(String actor, List<String> movies) {}

    此注解既适用于记录类，也适用于普通的 Java 类。

    通用 Bean 类型

    使用 `ParameterizedTypeReference` 构造函数来指定更复杂的目标类结构。 例如，要表示演员及其作品列表：

    List<ActorsFilms> actorsFilms = ChatClient.create(chatModel).prompt()
        .user("Generate the filmography of 5 movies for Tom Hanks and Bill Murray.")
        .call()
        .entity(new ParameterizedTypeReference<List<ActorsFilms>>() {});

    或使用低级别的ChatModelAPI 直接调用：

    BeanOutputConverter<List<ActorsFilms>> outputConverter = new BeanOutputConverter<>(
        new ParameterizedTypeReference<List<ActorsFilms>>() { });

String format = this.outputConverter.getFormat();
String template = """
        Generate the filmography of 5 movies for Tom Hanks and Bill Murray.
        {format}
        """;

Prompt prompt = PromptTemplate.builder().template(this.template).variables(Map.of("format", this.format)).build().create();

Generation generation = chatModel.call(this.prompt).getResult();

List<ActorsFilms> actorsFilms = this.outputConverter.convert(this.generation.getOutput().getText());

    Map 输出转换器

    以下代码片段展示了如何使用 `MapOutputConverter` 将模型输出转换为 Map 中的数字列表。

    Map<String, Object> result = ChatClient.create(chatModel).prompt()
        .user(u -> u.text("Provide me a List of {subject}")
                    .param("subject", "an array of numbers from 1 to 9 under they key name 'numbers'"))
        .call()
        .entity(new ParameterizedTypeReference<Map<String, Object>>() {});

    或使用低级别的ChatModelAPI 直接调用：

    MapOutputConverter mapOutputConverter = new MapOutputConverter();

String format = this.mapOutputConverter.getFormat();
String template = """
        Provide me a List of {subject}
        {format}
        """;

Prompt prompt = PromptTemplate.builder().template(this.template)
.variables(Map.of("subject", "an array of numbers from 1 to 9 under they key name 'numbers'", "format", this.format)).build().create();

Generation generation = chatModel.call(this.prompt).getResult();

Map<String, Object> result = this.mapOutputConverter.convert(this.generation.getOutput().getText());

    列表输出转换器

    以下代码片段展示了如何使用ListOutputConverter将模型输出转换为冰淇淋口味列表。

    List<String> flavors = ChatClient.create(chatModel).prompt()
                .user(u -> u.text("List five {subject}")
                            .param("subject", "ice cream flavors"))
                .call()
                .entity(new ListOutputConverter(new DefaultConversionService()));

    或使用低级别的ChatModel API直接调用：

    ListOutputConverter listOutputConverter = new ListOutputConverter(new DefaultConversionService());

String format = this.listOutputConverter.getFormat();
String template = """
        List five {subject}
        {format}
        """;

Prompt prompt = PromptTemplate.builder().template(this.template).variables(Map.of("subject", "ice cream flavors", "format", this.format)).build().create();

Generation generation = this.chatModel.call(this.prompt).getResult();

List<String> list = this.listOutputConverter.convert(this.generation.getOutput().getText());

    原生结构化输出

    如今，许多现代 AI 模型均原生支持结构化输出，其结果比基于提示的格式化更为可靠。Spring AI 通过原生结构化输出功能实现了这一支持。

    在使用原生结构化输出时，BeanOutputConverter 生成的 JSON Schema 会直接发送给模型的结构化输出 API，从而无需在提示词中添加格式指令。这种方法提供了：

    • 更高的可靠性：该模型保证输出符合模式定义。

    • 更简洁的提示词：无需附加格式指令

    • 性能更优：模型可在内部对结构化输出进行优化

    使用原生结构化输出

    要启用原生结构化输出，请使用 `AdvisorParams.ENABLE_NATIVE_STRUCTURED_OUTPUT` 参数：

    ActorsFilms actorsFilms = ChatClient.create(chatModel).prompt()
    .advisors(AdvisorParams.ENABLE_NATIVE_STRUCTURED_OUTPUT)
    .user("Generate the filmography for a random actor.")
    .call()
    .entity(ActorsFilms.class);

    此外，您还可以通过在ChatClient.Builder上调用defaultAdvisors()来全局设置：

    @Bean
ChatClient chatClient(ChatClient.Builder builder) {
    return builder
        .defaultAdvisors(AdvisorParams.ENABLE_NATIVE_STRUCTURED_OUTPUT)
        .build();
}

    支持原生结构化输出的模型

    以下模型目前支持原生结构化输出：

    • OpenAI：支持 JSON Schema 的 GPT-4o 及后续模型

    • Anthropic：Claude 3.5 Sonnet 及后续模型

    • Google GenAI：Gemini 1.5 Pro 及后续版本模型

    • Mistral AI：支持 JSON Schema 的 Mistral Small 及后续模型

    • Ollama：支持 JSON Schema 的模型（特定于模型；详见下方的Ollama 限制）

    原生结构化输出默认未启用，因为不同模型和提供商的支持程度差异显著。基于提示词的方法（默认方式）在所有模型中表现一致。仅在需要其提供的更强 API 级模式强制约束时才启用原生结构化输出，并始终针对您的具体模型版本进行测试。

    已知局限性

    Ollama：模型特定不稳定性

    并非所有 Ollama 模型都能可靠地遵守结构化输出模式约束。 特别是那些内置推理或“思考”模式的模型（例如qwen3:8b、qwen3.5:9b以及其他较新的 Qwen 变体）可能会将其内部推理轨迹以纯文本形式返回，而不是结构化 JSON，从而导致在BeanOutputConverter中发生反序列化错误，例如：

    StreamReadException: Unrecognized token 'The': was expecting (JSON String, Number, Array, Object or token 'null', 'true' or 'false')

    如果在 Ollama 中遇到此问题，请尝试使用不同的模型（例如llama3.1:latest），或者回退到基于默认提示的方法。 您还可以将useProviderStructuredOutput()与validateSchema()结合使用，以便自动重试格式错误的响应：

    ActorFilms actorFilms = chatClient.prompt()
    .user("Generate the filmography for a random actor.")
    .call()
    .entity(ActorFilms.class, spec -> spec
        .useProviderStructuredOutput()
        .validateSchema());
    OpenAI：不支持顶层数组

    OpenAI 结构化输出 API 不接受顶层 JSON 数组作为响应模式（参见OpenAI 社区讨论）。 启用原生结构化输出后请求一个List<T>将导致 API 错误。

    // Does NOT work with OpenAI native structured output:
List<ActorsFilms> films = chatClient.prompt()
    .user("Generate filmographies for Tom Hanks and Bill Murray.")
    .call()
    .entity(new ParameterizedTypeReference<List<ActorsFilms>>() {},
            spec -> spec.useProviderStructuredOutput()); // fails with OpenAI

    请使用以下替代方案之一：

    // Option 1: wrap the list in a container record
record FilmographyList(List<ActorsFilms> films) {}

FilmographyList result = chatClient.prompt()
    .user("Generate filmographies for Tom Hanks and Bill Murray.")
    .call()
    .entity(FilmographyList.class, spec -> spec.useProviderStructuredOutput());
List<ActorsFilms> films = result.films();

// Option 2: use the default prompt-based approach (no native output required)
List<ActorsFilms> films = chatClient.prompt()
    .user("Generate filmographies for Tom Hanks and Bill Murray.")
    .call()
    .entity(new ParameterizedTypeReference<List<ActorsFilms>>() {});

    内置 JSON 模式

    某些人工智能模型提供专用配置选项，以生成结构化（通常为 JSON）的输出。

    • OpenAI 结构化输出可确保您的模型生成严格符合您提供的 JSON Schema 的响应。您可以选择 JSON_OBJECT，以保证模型生成的消息是有效的 JSON；或者选择 JSON_SCHEMA，并配合提供的 schema，以确保模型生成的响应与所提供的 schema（spring.ai.openai.chat.response-format 选项）相匹配。

    • Ollama - 提供了一个 spring.ai.ollama.chat.format 选项，用于指定返回响应的格式。目前，唯一接受的值为 json。

    • Mistral AI 提供了一个 spring.ai.mistralai.chat.response-format 选项，用于指定返回响应的格式。将其设置为 { "type": "json_object" } 可启用 JSON 模式，从而确保模型生成的消息是有效的 JSON。此外，将其设置为 { "type": "json_schema" } 并配合提供的架构（schema），可启用原生的结构化输出支持，从而确保模型生成的响应符合您提供的架构。
