    Google 生成式 AI 聊天

    Google GenAI API 允许开发者通过 Gemini Developer API 或 Vertex AI，利用 Google 的 Gemini 模型构建生成式人工智能应用程序。 Google GenAI API 支持以多模态提示作为输入，并输出文本或代码。 多模态模型能够处理来自多种模态的信息，包括图像、视频和文本。例如，您可以向模型发送一盘曲奇饼干的图片，并要求它提供制作这些饼干的方法。

    Gemini 是由 Google DeepMind 开发的一系列生成式 AI 模型，专为多模态应用场景而设计。Gemini API 让您能够访问各种模型，例如 Gemini Flash-Lite、Gemini Flash 或 Gemini Pro。

    此实现提供两种身份验证模式：

    • Gemini 开发者 API：使用 API 密钥进行快速原型开发和开发工作。

    • Vertex AI：使用 Google Cloud 凭据进行具有企业功能的生产部署

    Gemini API 参考文档

    Prerequisites

    请选择以下认证方法之一：

    选项 1：Gemini 开发者 API（API 密钥）

    • 从Google AI Studio获取 API 密钥。

    • 将 API 密钥设置为环境变量或在您的应用程序属性中配置。

    选项 2：Vertex AI（Google Cloud）

    • 安装适用于您操作系统的 gcloud 命令行接口 (CLI)。

    • 运行以下命令进行身份验证。将 `PROJECT_ID` 替换为您的 Google Cloud 项目 ID，将 `ACCOUNT` 替换为您的 Google Cloud 用户名。

    gcloud config set project <PROJECT_ID> &&
gcloud auth application-default login <ACCOUNT>

    Auto-configuration

    Spring AI 的自动配置中，starter 模块的构件名称已发生重大变更。 有关更多信息，请参阅升级说明。

    Spring AI 为 Google GenAI 聊天客户端提供了 Spring Boot 自动配置功能。 要启用此功能，请在项目的 Maven `pom.xml` 或 Gradle `build.gradle` 构建文件中添加以下依赖：

    • Maven

    • Gradle

    <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-google-genai</artifactId>
</dependency>
    dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-model-google-genai'
}
    请参考依赖管理部分，将 Spring AI BOM 添加到您的构建文件中。

    聊天属性

    启用和禁用聊天自动配置现在通过带有前缀spring.ai.model.chat的顶层属性进行配置。

    要启用该功能，请设置 spring.ai.model.chat=google-genai（默认已启用）。

    要禁用该功能，请将 spring.ai.model.chat 设置为 none（或任何不等于 google-genai 的值）。

    此更改旨在支持配置多个模型。

    连接属性

    聊天模型属性

    spring.ai.google.genai.chat 前缀是用于配置 Google GenAI Chat 聊天模型实现的属性前缀。

    Property Description Default

    spring.ai.google.genai.chat.model

    支持使用的Google GenAI 对话模型包括：gemini-2.5-flash、gemini-2.5-flash-lite、gemini-2.5-pro、gemini-3.1-pro-preview、gemini-3.1-flash-lite和gemini-3.5-flash。

    gemini-2.5-flash

    spring.ai.google.genai.chat.response-mime-type

    text/plain

    text/plain：（默认）文本输出，或application/json：JSON 响应。

    spring.ai.google.genai.chat.google-search-retrieval

    使用 Google 搜索 grounding 功能。

    true or false, default false.

    spring.ai.google.genai.chat.include-server-side-tool-invocations

    当为真时，API 响应会在响应元数据中包含服务器端工具调用和响应（例如 Google 搜索调用），从而允许观察服务器的工具使用情况。此功能仅支持 Gemini Developer API (MLDev)，不支持 Vertex AI。请参阅 服务器端工具调用。

    false

    spring.ai.google.genai.chat.temperature

    控制输出的随机性。取值范围为 [0.0, 1.0]，包含端点值。越接近 1.0 的值会产生更多样化的回复，而越接近 0.0 的值通常会导致生成结果更加不可预测性较低。

    -

    spring.ai.google.genai.chat.top-k

    采样时考虑的最大 token 数量。生成过程结合了 Top-k 和核采样（nucleus sampling）。Top-k 采样会考虑概率最高的前 K 个 token 集合。

    -

    spring.ai.google.genai.chat.top-p

    采样时考虑的最大累积概率。生成过程结合了 Top-k 和核采样（nucleus sampling）。核采样会选取概率总和至少为 topP 的最小 token 集合。

    -

    spring.ai.google.genai.chat.candidate-count

    要返回的生成响应消息数量。该值必须在 [1, 8] 范围内（包含边界），默认为 1。

    1

    spring.ai.google.genai.chat.max-output-tokens

    生成 token 的最大数量。

    -

    spring.ai.google.genai.chat.frequency-penalty

    降低重复率的频率惩罚。

    -

    spring.ai.google.genai.chat.presence-penalty

    用于减少重复的惩罚项。

    -

    spring.ai.google.genai.chat.thinking-budget

    思考预算用于思考过程。请参阅思考配置。

    -

    spring.ai.google.genai.chat.thinking-level

    模型应生成的思维 token 级别。有效值：LOW、HIGH、THINKING_LEVEL_UNSPECIFIED。请参阅思维配置。

    -

    spring.ai.google.genai.chat.include-thoughts

    启用函数调用的思维签名。必需，以避免 Gemini 3 Pro 在工具调用循环期间出现验证错误。请参阅思维签名。

    false

    spring.ai.google.genai.chat.tool-callbacks

    用于与 ChatModel 注册的回调工具。

    -

    spring.ai.google.genai.chat.safety-settings

    用于控制安全过滤器的安全设置列表，定义方式参考Google GenAI 安全设置。每个安全设置均可包含方法、阈值和类别。

    -

    spring.ai.google.genai.chat.cached-content-name

    此请求要使用的缓存内容名称。当与use-cached-content=true一起设置时，将使用缓存的内容作为上下文。请参阅缓存内容。

    -

    spring.ai.google.genai.chat.use-cached-content

    是否使用可用的缓存内容。当设置为 true 且已设置 `cached-content-name` 时，系统将使用缓存的内容。

    false

    spring.ai.google.genai.chat.auto-cache-threshold

    自动缓存超过此令牌阈值的提示。启用后，大于此值的提示将自动缓存以供重用。设置为 null 可禁用自动缓存。

    -

    spring.ai.google.genai.chat.auto-cache-ttl

    自动缓存内容的生存时间（持续时间），格式为 ISO-8601（例如，PT1H 表示 1 小时）。仅在启用自动缓存时使用。

    PT1H

    spring.ai.google.genai.chat.enable-cached-content

    启用用于管理缓存内容的GoogleGenAiCachedContentServiceBean。

    true

    spring.ai.google.genai.chat.service-tier

    请求要使用的服务等级。有效值：STANDARD、PRIORITY、FLEX。

    -
    所有以 spring.ai.google.genai.chat 开头的属性都可以通过在 Prompt 调用中添加特定于请求的运行时选项来在运行时进行覆盖。

    运行时选项

    GoogleGenAiChatOptions.java 提供了模型配置，例如温度（temperature）、topK 等。

    启动时，默认选项可以通过 `GoogleGenAiChatModel(client, options)` 构造函数或 `spring.ai.google.genai.chat.*` 属性进行配置。

    在运行时，您可以通过向 `Prompt` 调用添加新的、特定于请求的选项来覆盖默认选项。 例如，要覆盖特定请求的默认温度：

    ChatResponse response = chatModel.call(
    new Prompt(
        "Generate the names of 5 famous pirates.",
        GoogleGenAiChatOptions.builder()
            .temperature(0.4)
        .build()
    ));
    除了针对特定模型的 GoogleGenAiChatOptions 之外，您还可以使用可移植的 ChatOptions 实例，该实例可通过 ChatOptions#builder() 创建。

    工具调用

    GoogleGenAiChatModel 不会在内部执行工具调用。 必须使用以下两种支持的方法之一在外部处理工具执行。

    通过 ChatClient 进行工具调用（推荐）

    建议使用带有ToolCallingAdvisor的ChatClient，该组件会自动注册并透明地管理同步和流式场景下的工具调用循环。

    public class WeatherService {

    @Tool(description = "Get the weather in location")
    public String weatherByLocation(@ToolParam(description= "City or state name") String location) {
        ...
    }
}

String response = ChatClient.create(this.chatModel)
        .prompt("What's the weather like in Boston?")
        .tools(new WeatherService())
        .call()
        .content();

    您还可以注册一个 `ToolCallback` 圈并将其直接传递：

    @Bean
ToolCallback weatherFunction() {
    return FunctionToolCallback.builder("weatherFunction", new MockWeatherService())
        .description("Get the weather in location. Return temperature in 36°F or 36°C format.")
        .inputType(Request.class)
        .build();
}

String response = ChatClient.create(this.chatModel)
        .prompt("What's the weather like in Boston?")
        .tools(weatherFunction)
        .call()
        .content();

    用户控制的工具执行

    当您需要直接访问ChatModel API 并希望完全控制工具调用循环时，请使用此模式。 直接调用ChatModel而无需使用ToolCallingAdvisor；自行检查工具调用情况，并使用ToolCallingManager驱动循环。

    ToolCallingManager toolCallingManager = ToolCallingManager.builder().build();

GoogleGenAiChatOptions options = GoogleGenAiChatOptions.builder()
        .toolCallbacks(ToolCallbacks.from(new WeatherService()))
        .build();

Prompt prompt = new Prompt("What's the weather like in Boston?", options);
ChatResponse response = chatModel.call(prompt);

while (response.hasToolCalls()) {
    ToolExecutionResult toolExecutionResult = toolCallingManager.executeToolCalls(prompt, response);
    prompt = new Prompt(toolExecutionResult.conversationHistory(), options);
    response = chatModel.call(prompt);
}

    有关更多信息，请参阅工具文档。

    服务端工具调用

    当通过 `googleSearchRetrieval(true)` 启用 Google 搜索或其他服务端工具时，模型会在服务端执行这些工具。默认情况下，这些调用对客户端不可见——您只能看到最终的文本响应。设置 `includeServerSideToolInvocations(true)` 可使 API 将服务端的工具调用和响应包含在响应内容中，从而让您能够观察模型搜索的内容以及接收到的结果。

    此功能仅支持Gemini 开发者 API（使用 MLDev/API 密钥进行身份验证）。它不支持Vertex AI。

    Configuration

    通过应用程序属性启用：

    spring.ai.google.genai.chat.google-search-retrieval=true
spring.ai.google.genai.chat.include-server-side-tool-invocations=true

    或在运行时通过编程方式：

    ChatResponse response = chatModel.call(
    new Prompt(
        "What are the latest developments in quantum computing?",
        GoogleGenAiChatOptions.builder()
            .model("gemini-2.0-flash")
            .googleSearchRetrieval(true)
            .includeServerSideToolInvocations(true)
            .build()
    ));

    访问服务器端工具调用元数据

    启用后，服务端工具调用将出现在响应消息元数据的 `serverSideToolInvocations` 键下：

    ChatResponse response = chatModel.call(prompt);

Map<String, Object> metadata = response.getResult().getOutput().getMetadata();

List<Map<String, Object>> invocations =
    (List<Map<String, Object>>) metadata.get("serverSideToolInvocations");

if (invocations != null) {
    for (Map<String, Object> invocation : invocations) {
        String type = (String) invocation.get("type");       // "toolCall" or "toolResponse"
        String id = (String) invocation.get("id");            // Unique invocation ID
        String toolType = (String) invocation.get("toolType"); // e.g., "GOOGLE_SEARCH_WEB"

        if ("toolCall".equals(type)) {
            Map<String, Object> args = (Map<String, Object>) invocation.get("args");
            // Inspect what the model searched for
        } else if ("toolResponse".equals(type)) {
            Map<String, Object> responseData = (Map<String, Object>) invocation.get("response");
            // Inspect what search results the model received
        }
    }
}

    列表中的每个条目包含：

    Field Description

    type

    要么是 `"toolCall"`（模型的调用请求），要么是 `"toolResponse"`（服务器的响应结果）。

    id

    用于将 `toolCall` 与其对应的 `toolResponse` 关联起来的唯一标识符。

    toolType

    服务器端工具的类型（例如：GOOGLE_SEARCH_WEB、GOOGLE_SEARCH_IMAGE、URL_CONTEXT、GOOGLE_MAPS）

    args

    (toolCall 仅) 传递给工具的参数

    response

    工具返回的结果。

    结合函数调用

    服务器端工具调用与客户端函数调用协同工作。您可以在同一请求中同时启用 Google 搜索（服务器端）和自定义函数（客户端）：

    ChatResponse response = chatModel.call(
    new Prompt(
        "What's the weather in San Francisco? Also search for the latest news about the city.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-2.0-flash")
            .googleSearchRetrieval(true)
            .includeServerSideToolInvocations(true)
            .toolCallbacks(List.of(
                FunctionToolCallback.builder("get_current_weather", new WeatherService())
                    .description("Get the current weather in a given location")
                    .inputType(WeatherRequest.class)
                    .build()))
            .build()
    ));

// The response contains:
// - Weather data from the client-side function call (executed locally)
// - Google Search invocations visible in metadata (executed server-side)
    服务端工具调用仅用于观测——客户端不会执行它们。为了避免干扰工具执行循环，这些调用在元数据中与客户端函数调用分开展示。

    思考配置

    Gemini 模型支持“思考”功能，使模型能够在生成回复之前进行更深入的推理。该功能通过ThinkingConfig进行控制，其中包括三个相关选项：thinkingBudget、thinkingLevel和includeThoughts。

    思考层级

    `thinkingLevel` 选项控制模型生成的推理 token 的深度。此功能适用于支持思考的模型（例如 Gemini 3 Pro Preview）。

    Value Description

    THINKING_LEVEL_UNSPECIFIED

    该模型使用其默认行为。

    MINIMAL

    符合大多数查询的“无思考”设置，最小化延迟。

    LOW

    低阶思维。推理 token 最少。

    MEDIUM

    大多数任务需要平衡的思维。

    HIGH

    深入思考。适用于需要深度分析和逐步推理的复杂问题。

    通过属性进行配置

    spring.ai.google.genai.chat.model=gemini-3.1-pro-preview
spring.ai.google.genai.chat.thinking-level=HIGH

    程序化配置

    import org.springframework.ai.google.genai.common.GoogleGenAiThinkingLevel;

ChatResponse response = chatModel.call(
    new Prompt(
        "Explain the theory of relativity in simple terms.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-3.1-pro-preview")
            .thinkingLevel(GoogleGenAiThinkingLevel.HIGH)
            .build()
    ));

    思考预算

    `thinkingBudget` 选项为思考过程设置了一个令牌预算：

    • 正值：思考的最大 token 数量（例如：8192）

    • 零 (0)：完全禁用思考功能

    • 未设置：模型将根据查询复杂度自动决定

    ChatResponse response = chatModel.call(
    new Prompt(
        "Solve this complex math problem step by step.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-2.5-pro")
            .thinkingBudget(8192)
            .build()
    ));

    选项兼容性

    thinkingLevel 和 thinkingBudget 是互斥的。 您不能在同一个请求中同时使用两者，否则会导致 API 错误。

    • 请使用 `thinkingLevel` 参数为Gemini 3.x 系列模型。Gemini 3 Pro 仅支持`LOW`和`HIGH`两个级别；而 Gemini 3 Flash 系列模型则支持所有级别（`MINIMAL`、`LOW`、`MEDIUM`、`HIGH`）。

    • 请使用 `thinkingBudget`（令牌数）为Gemini 2.5系列模型。

    您可以将 `includeThoughts` 与 `thinkingLevel` 或 `thinkingBudget` 中的任意一个结合使用（但不能同时使用两者）：

    // For Gemini 3.x (e.g. Pro): use thinkingLevel + includeThoughts
ChatResponse response = chatModel.call(
    new Prompt(
        "Analyze this complex scenario.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-3.1-pro-preview")
            .thinkingLevel(GoogleGenAiThinkingLevel.HIGH)
            .includeThoughts(true)
            .build()
    ));

// For Gemini 2.5: use thinkingBudget + includeThoughts
ChatResponse response = chatModel.call(
    new Prompt(
        "Analyze this complex scenario.",
        GoogleGenAiChatOptions.builder()
            .model("gemini-2.5-pro")
            .thinkingBudget(8192)
            .includeThoughts(true)
            .build()
    ));

    思维签名

    Gemini 3 Pro 引入了思维签名，这是一种不透明的字节数组，可在函数调用期间保留模型的推理上下文。当启用includeThoughts时，模型将返回思维签名，这些签名必须在工具调用循环的同一轮次中回传。

    当思维签名至关重要时

    重要提示：思维签名验证仅适用于当前轮次——具体而言，是在模型执行函数调用（包括并行和顺序调用）的工具调用循环期间。API 不会对对话历史中先前轮次的思维签名进行验证。

    根据Google 的文档：

    • 仅对当前回合内的函数调用强制执行验证。

    • 无需保留之前的签名。

    • 当前轮次函数调用中缺少签名会导致 Gemini 3 Pro 返回 HTTP 400 错误。

    • 对于并行函数调用，仅第一个 `functionCall` 部分携带签名。

    对于 Gemini 2.5 Pro 及更早版本的模型，思维签名是可选的，API 对此较为宽松。

    Configuration

    使用配置属性启用思维签名：

    spring.ai.google.genai.chat.model=gemini-3.1-pro-preview
spring.ai.google.genai.chat.include-thoughts=true

    或在运行时通过编程方式：

    ChatResponse response = chatModel.call(
    new Prompt(
        "Your question here",
        GoogleGenAiChatOptions.builder()
            .model("gemini-3.1-pro-preview")
            .includeThoughts(true)
            .toolCallbacks(callbacks)
            .build()
    ));

    通过 ChatClient 自动处理（推荐）

    在使用 ChatClient 与 ToolCallingAdvisor（推荐方法）时，Spring AI 会自动处理思维签名：

    1. 提取模型响应中的思维签名

    2. 在返回函数响应时，将它们附加到正确的 `functionCall` 部分。

    3. 在单次轮次内的函数调用中正确传播它们（包括并行和顺序调用）

    @Bean
ToolCallback weatherFunction() {
    return FunctionToolCallback.builder("weatherFunction", new WeatherService())
        .description("Get the weather in a location")
        .inputType(WeatherRequest.class)
        .build();
}

// Enable includeThoughts for Gemini 3 Pro with function calling
String response = ChatClient.create(this.chatModel)
        .prompt("What's the weather like in Boston?")
        .options(GoogleGenAiChatOptions.builder()
            .model("gemini-3.1-pro-preview")
            .includeThoughts(true)
            .build())
        .tools(weatherFunction)
        .call()
        .content();

    基于思维签名的用户可控工具执行

    在使用手动工具执行循环时，必须通过保留原始AssistantMessage（包含其元数据）来维护思维签名。Spring AI 在转换消息时会自动将签名附加到正确的functionCall部分。

    使用思维签名执行手动工具的要求：

    1. 从响应元数据中提取思维签名：

      AssistantMessage assistantMessage = response.getResult().getOutput();
Map<String, Object> metadata = assistantMessage.getMetadata();
List<byte[]> thoughtSignatures = (List<byte[]>) metadata.get("thoughtSignatures");

    2. 在返回函数响应时，请在消息历史中包含原始的 `AssistantMessage` 及其完整的元数据。Spring AI 将自动将思维签名附加到正确的 `functionCall` 部分。

    3. 对于 Gemini 3 Pro，若在当前轮次中未保留思维签名，将导致 API 返回 HTTP 400 错误。

    仅当前回合的函数调用需要思维签名。在开始新的对话回合（即完成一个函数调用轮次后），无需保留上一回合的签名。
    启用 includeThoughts 会增加 token 用量，因为思考过程会被包含在响应中。这会影响 API 成本，但能提供更好的推理透明度。

    Multimodal

    多模态是指模型同时理解和处理来自多种（输入）来源信息的能力，包括text、pdf、images、audio以及其他数据格式。

    Image, Audio, Video

    Google 的 Gemini AI 模型通过理解并整合文本、代码、音频、图像和视频来支持这一功能。 如需了解更多详情，请参阅博客文章 介绍 Gemini。

    Spring AI 的 `Message`接口通过引入 Media 类型来支持多模态 AI 模型。该类型包含消息中媒体附件的数据和信息，使用 Spring 的 `org.springframework.util.MimeType`以及一个 `java.lang.Object`来表示原始媒体数据。

    下面是一个从GoogleGenAiChatModelIT.java中提取的简单代码示例，展示了如何将用户文本与图像相结合。

    byte[] data = new ClassPathResource("/vertex-test.png").getContentAsByteArray();

var userMessage = UserMessage.builder()
			.text("Explain what do you see o this picture?")
			.media(List.of(new Media(MimeTypeUtils.IMAGE_PNG, data)))
			.build();

ChatResponse response = chatModel.call(new Prompt(List.of(this.userMessage)));

    Google GenAI 支持 PDF 输入类型。使用 `application/pdf` 媒体类型将 PDF 文件附加到消息中：

var userMessage = UserMessage.builder()

    缓存内容

    Google GenAI 的上下文缓存功能允许您缓存大量内容（如长文档、代码库或媒体），并在多个请求中重复使用。这显著降低了 API 成本，并提高了对相同内容的重复查询的响应延迟。

    Benefits

    • 降低成本：缓存 token 的计费费率远低于普通输入 token（通常便宜 75%-90%）

    • 性能提升：复用缓存内容可缩短大上下文的处理时间。

    • 一致性：相同的缓存上下文确保多次请求之间响应的一致性。

    缓存要求

    • 最小缓存大小：32,768 个 token（约 25,000 词）

    • 最大缓存时长：默认为 1 小时（可通过 TTL 配置）

    • 缓存内容必须包含系统指令或对话历史。

    使用缓存内容服务

    Spring AI 提供了 `GoogleGenAiCachedContentService` 用于程序化缓存管理。在使用 Spring Boot 自动配置时，该服务会自动进行配置。

    创建缓存内容

    @Autowired
private GoogleGenAiCachedContentService cachedContentService;

// Create cached content with a large document
String largeDocument = "... your large context here (>32k tokens) ...";

CachedContentRequest request = CachedContentRequest.builder()
    .model("gemini-2.5-flash")
    .contents(List.of(
        Content.builder()
            .role("user")
            .parts(List.of(Part.fromText(largeDocument)))
            .build()
    ))
    .displayName("My Large Document Cache")
    .ttl(Duration.ofHours(1))
    .build();

GoogleGenAiCachedContent cachedContent = cachedContentService.create(request);
String cacheName = cachedContent.getName(); // Save this for reuse

    在聊天请求中使用缓存内容

    创建缓存内容后，请在聊天请求中引用它：

    ChatResponse response = chatModel.call(
    new Prompt(
        "Summarize the key points from the document",
        GoogleGenAiChatOptions.builder()
            .useCachedContent(true)
            .cachedContentName(cacheName) // Use the cached content name
            .build()
    ));

    或通过配置属性：

    spring.ai.google.genai.chat.use-cached-content=true
spring.ai.google.genai.chat.cached-content-name=cachedContent/your-cache-name

    管理缓存内容

    GoogleGenAiCachedContentService 提供全面的缓存管理功能：

    // Retrieve cached content
GoogleGenAiCachedContent content = cachedContentService.get(cacheName);

// Update cache TTL
CachedContentUpdateRequest updateRequest = CachedContentUpdateRequest.builder()
    .ttl(Duration.ofHours(2))
    .build();
GoogleGenAiCachedContent updated = cachedContentService.update(cacheName, updateRequest);

// List all cached content
List<GoogleGenAiCachedContent> allCaches = cachedContentService.listAll();

// Delete cached content
boolean deleted = cachedContentService.delete(cacheName);

// Extend cache TTL
GoogleGenAiCachedContent extended = cachedContentService.extendTtl(cacheName, Duration.ofMinutes(30));

// Cleanup expired caches
int removedCount = cachedContentService.cleanupExpired();

    异步操作

    所有操作都有异步变体：

    CompletableFuture<GoogleGenAiCachedContent> futureCache =
    cachedContentService.createAsync(request);

CompletableFuture<GoogleGenAiCachedContent> futureGet =
    cachedContentService.getAsync(cacheName);

CompletableFuture<Boolean> futureDelete =
    cachedContentService.deleteAsync(cacheName);

    Auto-Caching

    当提示超过指定的令牌阈值时，Spring AI 可以自动缓存大型提示：

    # Automatically cache prompts larger than 100,000 tokens
spring.ai.google.genai.chat.auto-cache-threshold=100000
# Set auto-cache TTL to 1 hour
spring.ai.google.genai.chat.auto-cache-ttl=PT1H

    或者通过编程方式：

    ChatResponse response = chatModel.call(
    new Prompt(
        largePrompt,
        GoogleGenAiChatOptions.builder()
            .autoCacheThreshold(100000)
            .autoCacheTtl(Duration.ofHours(1))
            .build()
    ));
    自动缓存适用于一次性的大规模上下文。对于重复使用相同上下文的情况，手动创建和引用缓存内容更为高效。

    监控缓存使用情况

    缓存内容包含可通过服务访问的使用元数据：

    GoogleGenAiCachedContent content = cachedContentService.get(cacheName);

// Check if cache is expired
boolean expired = content.isExpired();

// Get remaining TTL
Duration remaining = content.getRemainingTtl();

// Get usage metadata
CachedContentUsageMetadata metadata = content.getUsageMetadata();
if (metadata != null) {
    System.out.println("Total tokens: " + metadata.totalTokenCount().orElse(0));
}

    最佳实践

    1. 缓存有效期：根据您的使用场景设置适当的 TTL。对于频繁更新的内容，使用较短的 TTL；对于静态内容，使用较长的 TTL。

    2. 缓存命名：使用描述性显示名称以便轻松识别缓存内容。

    3. 清理：定期清理过期的缓存以保持有序。

    4. 令牌阈值：仅缓存超过最低阈值（32,768 个令牌）的内容。

    5. 成本优化：跨多个请求复用缓存内容，以最大化节省成本。

    创建一个新的 Spring Boot 项目，并在您的 pom（或 gradle）依赖中添加spring-ai-starter-model-google-genai。

    在 `src/main/resources` 目录下添加一个 `application.properties` 文件，以启用并配置 Google GenAI 聊天模型：

    使用 Gemini 开发者 API（API 密钥）

    spring.ai.google.genai.api-key=YOUR_API_KEY
spring.ai.google.genai.chat.model=gemini-2.5-flash
spring.ai.google.genai.chat.temperature=0.5

    使用 Vertex AI

    spring.ai.google.genai.project-id=PROJECT_ID
spring.ai.google.genai.location=LOCATION
spring.ai.google.genai.chat.model=gemini-2.5-flash
spring.ai.google.genai.chat.temperature=0.5
    将 project-id 替换为您的 Google Cloud 项目 ID，location 为 Google Cloud 区域，例如 us-central1、europe-west1 等……

    每个模型都有其支持的特定区域列表，您可以在模型页面中找到该列表。

    这将创建一个 GoogleGenAiChatModel 实现，您可以将其注入到您的类中。以下是一个使用聊天模型进行文本生成的简单 @Controller 类的示例。

    @RestController
public class ChatController {

    private final GoogleGenAiChatModel chatModel;

    @Autowired
    public ChatController(GoogleGenAiChatModel chatModel) {
        this.chatModel = chatModel;
    }

    @GetMapping("/ai/generate")
    public Map generate(@RequestParam(value = "message", defaultValue = "Tell me a joke") String message) {
        return Map.of("generation", this.chatModel.call(message));
    }

    @GetMapping("/ai/generateStream")
	public Flux<ChatResponse> generateStream(@RequestParam(value = "message", defaultValue = "Tell me a joke") String message) {
        Prompt prompt = new Prompt(new UserMessage(message));
        return this.chatModel.stream(prompt);
    }
}

    手动配置

    GoogleGenAiChatModel 实现了 ChatModel，并使用 com.google.genai.Client 连接到 Google GenAI 服务。

    将 `spring-ai-google-genai` 依赖添加到您的项目的 Maven `pom.xml` 文件中：

    <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-google-genai</artifactId>
</dependency>

    或者将其添加到您的 Gradle `build.gradle` 构建文件中。

    dependencies {
    implementation 'org.springframework.ai:spring-ai-google-genai'
}
    请参考依赖管理部分，将 Spring AI BOM 添加到您的构建文件中。

ChatResponse response = this.chatModel.call(

    Client genAiClient = Client.builder()

var chatModel = new GoogleGenAiChatModel(genAiClient,

    从 Vertex AI Gemini 迁移

    如果您之前使用的是已被移除的 Vertex AI Gemini 实现（spring-ai-vertex-ai-gemini），请迁移到 Google GenAI：

    主要区别：

    1. SDK：Google GenAI 现已改用新的 com.google.genai.Client，而不再使用 com.google.cloud.vertexai.VertexAI。

    2. 身份验证：支持 API 密钥和 Google Cloud 凭据（Vertex AI 模式）

    3. 包名：类位于 org.springframework.ai.google.genai，而非 org.springframework.ai.vertexai.gemini

    4. 属性前缀：使用 spring.ai.google.genai 而非 spring.ai.vertex.ai.gemini

    Google GenAI 既支持使用 API 密钥进行快速原型开发，也支持通过 Google Cloud 凭据在 Vertex AI 上进行生产部署。
