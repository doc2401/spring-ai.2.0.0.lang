    Docker 模型运行器聊天

    Docker Model Runner 是一款人工智能推理引擎，提供来自 各种提供商 的广泛模型。

    Spring AI 通过复用现有的基于 OpenAI 的 ChatClient 与 Docker Model Runner 集成。为此，请将基础 URL 设置为 localhost:12434/engines/v1，并从提供的 LLM 模型 中选择一个。

    检查 DockerModelRunnerWithOpenAiChatModelIT.java 测试，以了解如何使用 Docker Model Runner 与 Spring AI。

    Prerequisite

    • 下载适用于 Mac 的 Docker Desktop 4.40.0。

    请选择以下选项之一以启用模型运行器：

    选项 1：

    • 启用模型运行器：docker desktop enable model-runner --tcp 12434。

    • 将 base-url 设置为 localhost:12434/engines/v1

    选项 2：

    • 启用模型运行器 docker desktop enable model-runner。

    • 使用 Testcontainers 并将 base-url 设置为如下：

    @Container
private static final DockerModelRunnerContainer DMR = new DockerModelRunnerContainer("alpine/socat:1.7.4.3-r0");

@Bean
public OpenAiChatModel chatModel() {
	var baseUrl = DMR.getOpenAIEndpoint();
	return OpenAiChatModel.builder()
		.options(OpenAiChatOptions.builder().baseUrl(baseUrl).apiKey("test").build())
		.build();
}

    您可以通过阅读使用 Docker 本地运行大型语言模型博客文章来了解更多关于 Docker Model Runner 的信息。

    Auto-configuration

    自 1.0.0.M7 版本以来，Spring AI 启动器模块的工件 ID 已更名。依赖名称现在应遵循针对模型、向量存储和 MCP 启动器的更新命名模式。 有关更多信息，请参阅升级说明。

    Spring AI 为 OpenAI Chat Client 提供了 Spring Boot 自动配置功能。 要启用该功能，请将以下依赖添加到项目的 Maven `pom.xml` 文件中：

    <dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-openai</artifactId>
</dependency>

    或在您的 Gradle `build.gradle` 构建文件中添加以下内容。

    dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-model-openai'
}
    请参考依赖管理部分，将 Spring AI BOM 添加到您的构建文件中。

    聊天属性

    重试属性

    前缀 `spring.ai.retry` 用作属性前缀，允许您为 OpenAI 聊天模型配置重试机制。

    Property Description Default

    spring.ai.retry.max-attempts

    最大重试尝试次数。

    10

    spring.ai.retry.backoff.initial-interval

    指数退避策略的初始睡眠时长。

    2 秒。

    spring.ai.retry.backoff.multiplier

    退避间隔倍数。

    5

    spring.ai.retry.backoff.max-interval

    最大退避时长。

    3 分钟。

    spring.ai.retry.on-client-errors

    如果为假，则抛出 NonTransientAiException 异常，并且不要针对 `4xx` 客户端错误代码进行重试。

    false

    spring.ai.retry.exclude-on-http-codes

    不应触发重试的 HTTP 状态码列表（例如，用于抛出 NonTransientAiException）。

    empty

    spring.ai.retry.on-http-codes

    应触发重试的 HTTP 状态码列表（例如，用于抛出 TransientAiException）。

    empty

    连接属性

    spring.ai.openai 前缀用作连接 OpenAI 的属性前缀。

    Property Description Default

    spring.ai.openai.base-url

    要连接的 URL。必须设置为 localhost:12434/engines/v1

    -

    spring.ai.openai.api-key

    任意字符串

    -

    配置属性

    启用和禁用聊天自动配置现在通过带有前缀spring.ai.model.chat的顶层属性来完成。

    要启用，请设置 spring.ai.model.chat=openai（默认已启用）。

    要禁用该功能，请将 spring.ai.model.chat=none（或任何与 openai 不匹配的值）设置为其他值。

    此更改允许在应用程序中配置多个模型。

    spring.ai.openai.chat 前缀是用于配置 OpenAI 聊天模型实现的属性前缀。

    Property Description Default

    spring.ai.openai.chat.enabled（已移除且不再有效）

    启用 OpenAI 聊天模型。

    true

    spring.ai.model.chat

    启用 OpenAI 聊天模型。

    openai

    spring.ai.openai.chat.base-url

    可选，覆盖 `spring.ai.openai.base-url` 以提供特定于聊天的 URL。必须设置为 `localhost:12434/engines/v1`。

    -

    spring.ai.openai.chat.api-key

    可选参数用于覆盖 spring.ai.openai.api-key，以提供特定于聊天的 API 密钥。

    -

    spring.ai.openai.chat.model

    要使用的LLM 模型

    -

    spring.ai.openai.chat.temperature

    控制生成补全结果表面创造力的采样温度。较高的值会使输出更加随机，而较低的值则使结果更加聚焦和确定性。不建议对同一补全请求同时修改温度和 top_p，因为这两个设置的交互作用难以预测。

    0.8

    spring.ai.openai.chat.frequency-penalty

    介于 -2.0 和 2.0 之间的数字。正值会根据文本中现有 token 的频率对新 token 进行惩罚，从而降低模型逐字重复相同内容的概率。

    0.0f

    spring.ai.openai.chat.max-tokens

    生成式对话补全的最大 token 数量。输入 token 总数与生成 token 总数之和受限于模型的上下文长度。

    -

    spring.ai.openai.chat.n

    为每个输入消息生成的聊天完成选项数量。请注意，您将根据所有选项中生成的 token 总数被收费。请将 n 设置为 1 以最小化成本。

    1

    spring.ai.openai.chat.presence-penalty

    -2.0 到 2.0 之间的数字。正值会根据新词是否出现在当前文本中对其进行惩罚，从而提高模型讨论新话题的可能性。

    -

    spring.ai.openai.chat.response-format

    指定模型必须输出的格式的物体。设置为 `{ "type": "json_object" }` 可启用 JSON 模式，确保模型生成的消息是有效的 JSON。

    -

    spring.ai.openai.chat.seed

    此功能处于测试版。如果指定了种子值，我们的系统将尽最大努力进行确定性采样，确保使用相同种子和参数的重复请求返回相同结果。

    -

    spring.ai.openai.chat.stop

    最多 4 个序列，在此序列中 API 将停止生成更多 token。

    -

    spring.ai.openai.chat.top-p

    另一种替代温度采样的方法是核采样（nucleus sampling），该模型会考虑概率质量排名前 p 的 token 结果。例如，0.1 表示仅考虑占据前 10% 概率质量的 token。我们通常建议调整此参数或温度参数，但不同时调整两者。

    -

    spring.ai.openai.chat.tools

    模型可能调用的工具列表。目前仅支持函数作为工具。使用此功能提供模型可生成 JSON 输入的函数列表。

    -

    spring.ai.openai.chat.tool-choice

    控制模型调用哪个（如果有）函数。none 表示模型不会调用函数，而是生成消息；auto 表示模型可以在生成消息或调用函数之间进行选择。通过指定特定函数 {"type": "function", "function": {"name": "my_function"}} 会强制模型调用该函数。如果没有函数存在，默认值为 none；如果存在函数，默认值为 auto。

    -

    spring.ai.openai.chat.user

    代表您最终用户的唯一标识符，有助于 OpenAI 监控和检测滥用行为。

    -

    spring.ai.openai.chat.stream-usage

    （仅适用于流式传输）设置为添加一个包含整个请求的令牌使用统计信息的额外块。此块的choices字段为空数组，而所有其他块也将包含一个使用字段，但其值为 null。

    false

    spring.ai.openai.chat.tool-callbacks

    用于与 ChatModel 注册的回调工具。

    -
    所有以 spring.ai.openai.chat 开头的属性都可以通过向 Prompt 调用添加特定的请求级运行时选项来在运行时覆盖。

    运行时选项

    OpenAiChatOptions.java 提供了模型配置，例如要使用的模型、温度、频率惩罚等。

    启动时，可以通过 `OpenAiChatModel(api, options)` 构造函数或 `spring.ai.openai.chat.*` 属性来配置默认选项。

    在运行时，您可以通过向 `Prompt` 调用中添加新的、特定于请求的选项来覆盖默认选项。 例如，若要为特定请求覆盖默认的模型和温度：

    ChatResponse response = chatModel.call(
    new Prompt(
        "Generate the names of 5 famous pirates.",
        OpenAiChatOptions.builder()
            .model("ai/gemma3:4B-F16")
        .build()
    ));
    除了针对特定模型的OpenAiChatOptions之外，您还可以使用通过ChatOptions#builder()创建的便携式ChatOptions实例。

    函数调用

    当选择支持该功能的模型时，Docker 模型运行器支持工具/函数调用。

    您可以将自定义的 Java 函数注册到 ChatModel，并让提供的模型智能地选择输出一个包含调用一个或多个已注册函数所需参数的 JSON 对象。 这是一种将大语言模型能力与外部工具和 API 连接起来的强大技术。

    工具示例

    以下是使用 Docker Model Runner 工具调用与 Spring AI 配合的简单示例：

    spring.ai.openai.api-key=test
spring.ai.openai.base-url=http://localhost:12434/engines/v1
spring.ai.openai.chat.model=ai/gemma3:4B-F16
    public class WeatherService implements Function<WeatherService.Request, WeatherService.Response> {

    public record Request(String location, String unit) {}
    public record Response(double temp, String unit) {}

    @Override
    public Response apply(Request request) {
        double temperature = request.location().contains("Amsterdam") ? 20 : 25;
        return new Response(temperature, request.unit);
    }
}
    ToolCallback weatherCallback = FunctionToolCallback.builder("getCurrentWeather", new WeatherService())
    .description("Get the weather in location")
    .inputType(WeatherService.Request.class)
    .build();

var response = chatClient.prompt()
    .user("What is the weather in Amsterdam and Paris?")
    .tools(weatherCallback)
    .call()
    .content();

    在此示例中，当模型需要天气信息时，会自动调用WeatherService，从而获取实时天气数据。 预期响应为：“阿姆斯特丹当前气温为 20 摄氏度，巴黎当前气温为 25 摄氏度。”

    了解更多关于工具调用的信息。

    示例控制器

    创建一个新的 Spring Boot 项目，并在您的 pom（或 gradle）依赖中添加spring-ai-starter-model-openai。

    在 `src/main/resources` 目录下添加一个 `application.properties` 文件，以启用并配置 OpenAI 聊天模型：

    spring.ai.openai.api-key=test
spring.ai.openai.base-url=http://localhost:12434/engines/v1
spring.ai.openai.chat.model=ai/gemma3:4B-F16

# Docker Model Runner doesn't support embeddings, so we need to disable them.
spring.ai.model.embedding=none

    这是一个简单的示例，展示了如何使用聊天模型进行文本生成的 `@Controller` 类。

    @RestController
public class ChatController {

    private final OpenAiChatModel chatModel;

    @Autowired
    public ChatController(OpenAiChatModel chatModel) {
        this.chatModel = chatModel;
    }

    @GetMapping("/ai/generate")
    public Map generate(@RequestParam(value = "message", defaultValue = "Tell me a joke") String message) {
        return Map.of("generation", this.chatModel.call(message));
    }

    @GetMapping("/ai/generateStream")
	public Flux<ChatResponse> generateStream(@RequestParam(value = "message", defaultValue = "Tell me a joke") String message) {
        Prompt prompt = new Prompt(new UserMessage(message));
        return this.chatModel.stream(prompt);
    }
}
